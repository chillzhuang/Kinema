# 封面设计 cover

```bash
python3 -m kinema cover x --all [--mock] [--desc "本章画面"]
```

## 1. 比例：双套必须全出

默认竖 3:4 ＋ 横 4:3 **双套必须全出，勿缩单版**。Studio 按容器自动适配：

| 容器 | 取哪套 |
|---|---|
| 项目卡横幅 / 章节缩略 | 4:3 |
| 详情主视觉 | 3:4 |
| 灯箱 | 双版可翻 |

其他比例：`--aspects` 任意比例按短边 1080 推导，`--size` 直给像素。

## 1.5 全画风公共契约

以下规则适用于所有 profile 和 route Skill；后面的 key visual 工法栈只是角色/故事驱动
画风的一个实现，不得把所有题材都做成同一种人物海报。

### 信息与对象

- 系列主视觉与章节封面是两个对象。系列封面建立品牌/世界观；章节封面必须有自己的无字
  背景和准确主标题，路径不能指向 `series_*`。
- 主标题、作者/创作者、副题只能来自已核实的项目元数据；项目品牌名不能冒充章节标题。
  `chapter.title` 是裸内容标题，序号只在 `chapter.id/order` 与封面组件中出现。
- 多书、多产品或多故事共用一个项目时，若引擎只有项目级排版标题，必须显式选择单对象项目
  或补齐章节级标题能力；不能静默用项目品牌名生成章节成品。

### 阵容

缺省阵容取 `role` 含「主」的角色优先、上限 3 人；`role` **只排序不筛人**——正好
3 人的项目怎么设 role 都是全员上封面，`desc` 里写「不要出现某角色」压不住引擎注入
的阵容句（带外观全文的正向指令更强势）。要撵人或改序用 `cover --cast 名,名`
（按给定顺序全收、错名硬拦），`--cast none` 不注入阵容句、构图全交 `desc`。

### 视觉命题

每张封面在 `desc` 中先确定一个可视化命题：**一个主主体 + 一个关系/冲突 + 一个环境层**。
主体数量、动作、材质、色彩和符号必须由当前 profile 决定：角色驱动风格可以用人物，图书/解说
优先用观点对应的对象或隐喻，产品/展示优先用产品本体，绘本优先用一个可读的故事动作。
禁止所有画风共用“正脸人物 + 大场景 + 粒子 + 大字”的默认模板。

### 可读性与交付

- 3:4 与 4:3 必须分别构图；不得用竖图硬裁横图。
- 画面必须有真实标题安全区，标题不压脸、不压关键主体、不贴边；缩到 84px 仍要看出
  主标题轮廓、主体和主色对比。
- 默认“无字 key visual → 后置题字/排版”两段式。AI 题字逐字 Read 校验；文字错误、占位
  标题、品牌名冒充章节标题、主体过多或缩略图不可读，均判封面不通过。
- 视觉验收至少检查：系列/章节路径是否分离、标题与元数据是否一致、两个比例是否存在、
  原图与缩略图是否都能读懂。封面不过，不得继续合成或交付。

### 缺省画面命题的取材（没有 `--desc` 时）

`run` 收尾的自动封面没有指挥层写的 desc，引擎按数据拼画面命题，取材链固定：

- 背景：顶层 `scene` > 登记的取景地 `scenes[]` 前两处的 desc。只读顶层的话，按规范
  把取景地登记在 `scenes[]` 的项目反而没有背景，工法栈里的世界观意象会自行编造一个
  与本剧无关的世界。
- 章节命题：`--desc` > 章节 `cover_prompt` > 章节 `theme`。
- 工法栈按媒介分档：写实档（`image.identity_sheet`）用电影海报档——纵深与元素编排只取
  取景地里真实存在的物件与光源，不添加能量流、符纹、粒子或世界观符号；其余画风沿用
  动画 key visual 档。共用条款只写一份（`pipeline/cover._dna`）。

自动封面仍只是缺省：要一张有命题的封面，按 §1.5 写 `--desc` 重出。

## 2. 两段式生成

### 2.1 第一段 · 无字 key visual 背景

产物 `*_bg` 是真源。卡片浮层标题 / 84px 缩略**必须消费无字版**。

### 2.2 第二段 · AI 题字（缺省）

以无字背景为首参考再生成。约束：

- 标题 = logo 级设计元素；
- 字数钉死 ＋ 逐字复述压错字；
- 白名单式防字地板；
- 章节题字带系列封面成品声明「字形沿用」，锁系列感。

> **引擎无 OCR，题字后指挥层必须 `Read` 查错字。** 错了 `--force` 重滚，或退逃生舱。

### 2.3 逃生舱 · `--typeset-title`

ffmpeg 排版后置：零成本、字绝对精确。`--font song|kai|hei|yuan` 仅此模式可用。

## 3. 产物

落 `assets/covers/`。`*_bg_<比例>.png` 无字真源与成品并存。

## 4. 缺口是怎么被发现的

`cover` 是独立的付费生图命令，不在 `gen-image`/`assemble` 等 stage 链里，也不被任何 stage 调用；
只有 `run` 一条龙收尾经 `_run_cover` 补一次本章封面（系列主视觉缺席时一并出、已在盘的不重生，
此时生图收尾的提醒以 `warn_cover=False` 关闭）。分步跑各 stage 时漏做没有硬性后果，所以缺口靠
三处互补的点名暴露：

| 处 | 判据 | 覆盖 |
|---|---|---|
| `cli._warn_cover_missing`（`gen-image` 收尾） | 查盘 `assets/covers/series*.png` 与 `<cid>*.png` | 系列 + 章节 |
| lint `cover_missing` | 纯文档：正镜图齐且章节 `cover` 为空 | 章节（Studio lint 面板与 `_lint_gate` 同步可见） |
| Studio 卡片标记 | `cover_missing` / 章节 `cover` 为空 | 项目卡 `NO COVER` 角标、项目页主视觉占位、章节表上方汇总行 |

收尾提醒挂在 `stage_gen_image` 的**两条出口**：正常收尾与 `if not plan: return`。
后者不可省——图出齐后重跑同一条命令走的就是空计划出口；agent 出图模式更彻底，
首轮抛「工单已开」到不了末尾，画完重跑正好落空计划，两条路都会绕开末尾那次调用。

Studio 卡片图源是**三级回落**：封面 → 成片海报帧 → 首个正镜分镜图
（`scanner._shot_thumb`，弃镜/转场镜判据复用 `variation.active_shots`）。
分镜图只是缩略图兜底，不进 `cover`/`covers` 表，也不改变 `cover_missing` 判定——
否则兜底图源顶上来之后，缺口看起来就像已经做过封面了。项目页的主视觉位**不放兜底图**，
缺封面时给占位块：那个位置放海报帧会直接让人以为封面已出。

## 5. 守卫

`test_cover` 覆盖：题字三硬约束 / 两段式源级接线 / 工法栈五条 / 主角优先阵容 ≤3 /
`TestCoverCast`（`--cast` 显式点名与排除）/
`REF_BASE` 复用 / `cmd_cover` 双路 `desc`+`ref_base` /
`TestCoverReminderReachesEveryExit`（空计划出口照样点名系列与本章）。
`test_variation.TestCoverMissing` 钉 lint 维度的三条判据边界；
`test_studio_routes.TestCoverFallbackChain` 钉三级回落与「兜底不冒充封面」。
