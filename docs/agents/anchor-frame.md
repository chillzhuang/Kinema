# 首帧锚定（anchor_frame）

分镜图以 `role=first_frame` 硬锁为片段第 0 帧，**不发末帧、镜间保持硬切**。
判据单一真源 `engine/kinema/pipeline/anchorframe.py`；渲染接线在
`cli.stage_gen_video`（`_shot_plan` 的 ③′ 支 + `_warn_anchor_tradeoff`）。

## 它补的是哪一格

native 的缺省档是**全能参考**：分镜图以 `role=reference_image` 附发，模型据它调和出
开头几帧。人工审过的那张分镜图因此**不是成片的第 0 帧**——实测同一镜的片段首帧
与分镜图在构图、主体姿态与陈设上都不是同一个镜头。要让首帧硬锁在审过的画面上，
协议上只有 `role=first_frame` 一条路。

而另一条到达首帧任务的通道是首尾帧衔接（`framechain`），它同时把下一镜的分镜图
钉成本镜末帧，接缝处随之不是硬切——「首帧要锁」和「镜间要硬切」两个诉求在那条
通道的数据模型上被绑成一个开关，单镜取不到「只锁首帧」这一态。

四档请求拓扑（native）：

| 档 | 分镜图角色 | 末帧 | 参考图通道 | 镜间 |
|---|---|---|---|---|
| 全能参考（缺省） | `reference_image` | 不发 | 板 + 设定图 | 硬切 |
| 尾帧接力 `tail_relay` | `reference_image` | 不发 | 板 + 设定图 + 上镜真实末帧 | 软承接 |
| **首帧锚定 `anchor_frame`** | **`first_frame`** | **不发** | **全部让位** | **硬切** |
| 首尾帧衔接 `frame_chain` | `first_frame` | 下一镜分镜图 | 全部让位 | 无缝焊接 |

## 代价（必须先说清）

首帧任务与参考媒体官方互斥（适配器亦硬拦），所以本档下**角色/场景/道具设定图、
简笔板、尾帧接力三条附发通道全部让位**，跨镜一致性只剩分镜图本身与文字角色锚
（`cast_anchor` 照发）。

- 划算：分镜图已经把该镜的外观与空间画定，且该镜的角色从头到尾在画面里；
- 不划算：角色中途才入画、远景看不清脸、或需要设定图补细节的镜。

引擎在整章第一次判出锚定时点名一次让位的通道（`_warn_anchor_tradeoff`）——
静默让位＝配置上设定图仍然挂着，实际却没有参与生成。

## 开关

```text
章级   章节 json 顶层 anchor_frame: true
镜级   shots[].anchor_frame: true          （单镜属性，无「焊缝两端」概念）
本次   gen-video --anchor-frame            （运行时覆盖，不落盘）
```

三者任一成立即生效，且**仅 native**：dubbed 恒走参考媒体（`ref_audio` 与首帧互斥），
kenburns 不调用视频模型。

## 优先级与互斥

`cli._shot_plan` 里锚定**只否决缺省档那一支**：

- V2V（`reference_video`）与 previz 末帧**优先**——那两支已各自占用了图的角色与末帧槽；
- 衔接参与镜（`chained` 或 `welded_in`）本就是首帧任务，锚定是空操作，
  且**不打锚定标记**：同一行既写「末帧=镜N」又写「镜间硬切」是自相矛盾；
- 显式参考孤岛表态（`sketch.reference`）仍然生效——两个镜级显式表态里更具体的那个说了算；
- 尾帧接力自动失效（`_relay_plan` 要求本镜挂得上参考图），让位清单里会点名。

## 可见性

- 阶段抬头：`· 首帧锚定(章级)·镜间硬切`
- 逐镜（dry-run 清单与真发日志同源）：`· 首帧锚定(分镜图=第0帧·无参考图·镜间硬切)`
- 让位告警：整章一次，列出被关掉的通道

## 守卫

`engine/tests/test_anchorframe.py`：判据边界（opt-in / 仅 native / 镜级独立）·
gen-video 接线（章级/镜级/CLI 覆盖各自的作用范围）· 三条让位通道点名一次且
不提用户没要过的那条 · 锚定镜一张设定图都不进请求 · 衔接章不受影响。

同文件另钉一组**配额裁剪点名**（`_video_sheet_refs` 的 `dropped`）：设定图挂载
超过 7 张时被丢掉的项必须指名道姓，且与张数同行——「设定图×7」单独出现读起来
像「都发出去了」，而作者显式写进 `shots[].props` 的道具可能正是被丢的那一个。
