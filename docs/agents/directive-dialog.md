# 指令台 openDirectiveDialog

**实现真源** `app/components.js`

## 1. 规则

**「把指令交给 AI」的按钮一律走指令台 `openDirectiveDialog`，不做一点即复制。**

## 2. 为什么

这类按钮拼的是**半成品模板**，末尾留着「需求：\<在此填写\>」这样的槽。直接复制等于把「回去自己改
尖括号」这道工序丢给用户。实测两个后果：

1. 忘了改，就把 `<在此写打磨方向>` 原样粘给 AI；
2. 干脆不用按钮、自己手打一句没有定位坐标的话，AI 又得满仓库找文件。

## 3. 指令台三段式

```
指令原文（只读 · 实时预览合并结果）
      ↓
你的需求（textarea）
      ↓
合并后复制（⌘/Ctrl+Enter 直达；复制后主钮亮「✓ 已复制」再收起）
```

## 4. 需求行由组件唯一生成

**调用点一个字都不许自己写。** 调用点只给两个参数：

| 参数 | 内容 |
|---|---|
| `directive` | 指令正文，**不含**需求行 |
| `ask` | 占位词，如 `在此写配音要求` |

组件恒补末行 `需求：<ask>`，并做行内琥珀高亮。

### 4.1 为什么只走一条路

两条路并存（指令自带槽的走就地替换；没槽的把需求追加成末尾【我的需求】面板）的后果：
同一个弹层在不同按钮下长两个样（一处行内高亮、一处底部一整块），**用户一眼就看出「风格不统一」
并点名**；而且槽文案与指令正文分两处写，改一处忘一处就静默漂移。

只此一条路，全部弹层结构逐像素一致，槽与正文也不可能对不上——正文里根本没有槽。

## 5. 守卫

`test_directive_dialog` 钉死：视图层出现以「需求：」开头的字面量，或 `slot:` / `*_SLOT` /
【我的需求】复活，即失败。

## 6. 文案纪律

| 类型 | 命名 | 示例 |
|---|---|---|
| 指令类按钮 | 「⧉ XX指令」，**不带「复制」「生」字** | `⧉ 改镜指令`（只改运镜文案） `⧉ 改图指令`（image_prompt 增量融合+重生图片） `⧉ 改板指令`（简笔板拍序列） `⧉ 视频指令` `⧉ 配音指令` `⧉ 拆书指令` |
| 动作型入口 | 保留原名，但同样走指令台 | `⧉ 打磨本集` `⧉ 调校设定` `⧉ 扩写正文` `⧉ 抽为角色 / 道具 / 场景` `AI 编排指令` |
