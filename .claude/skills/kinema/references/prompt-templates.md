# 提示词模板（阶段3 参考）

> **双语规范与字段全集见 `storyboard.md`**（image_prompt 中文主 / image_prompt_en 英文辅 /
> negative_prompt 负面约束 / 工业字段中英对照）。本文件是各模型的措辞模板速查。

## 图像提示词（image_prompt）

结构：**主体 + 动作 + 场景 + 风格块 + 构图 + 比例标注（按项目主比例）**

```
[主体，含 character_block 里的角色特征] + [动作/姿态] + [场景/道具] +
[美术风格：画风、配色（复用 style.palette）] + [居中构图，主体在安全区] + 比例标注
```

要点：
- **每镜都拼上 `style.character_block`**，保证角色/画风一致。
- 中文写作即可（Seedream/通义中文理解强）。
- **比例标注跟随项目主比例**：竖屏项目写"竖屏 9:16 / 竖版构图 / 居中"；横屏项目写
  "横屏 16:9 电影构图"；方形写"方形 1:1 居中构图"——避免出图与画布不符导致裁切。
- 需要文字上屏时靠 caption（字幕烧录），**别依赖模型在图里写字**——引擎给每条图像提示词
  缺省加了防字地板（「避免出现：字幕、画面文字、水印」），画面本体一律无字。
  例外只有 `game_sim`（HUD）· `explainer`（信息图）两个画风，它们在 models.yaml 里
  显式关掉了地板；榜单徽章/气泡/对话框的文字全是 ASS 后置烧录，同样要求图本体干净。

示例（番茄工作法·扁平插画）：
```
扁平插画风，一个戴眼镜的年轻上班族瘫在书桌前发呆，桌上堆满待办便签，
暖橙#FF7A45 与奶白#FFF7ED 配色，圆润几何形状，居中构图，主体在竖屏安全区内，竖屏 9:16
```

## 视频提示词（video_prompt）

写作规则以 [video-prompting.md](video-prompting.md) 为准；本节只提供字段组织示例。
先核对实际附发素材，再描述需要发生的变化。动作幅度、速度与运镜服务于剧情，
不默认慢速，不强制每镜都有微动、环境运动或起落缓冲。

- 简单动作使用正文即可；多个关键事件需要安排先后时才写 `sketch.beats`。
  时间格式由 provider 决定，需要明确卡点时才填 `t`，不按镜长强制拆拍。
- `camera` 与 `sfx` 是共享字段，中英请求都保留原值、只切换标签，不自动翻译。
  英文正文无需再复述运镜和音效；直接相同的文字由引擎去重，语义重复由作者整理。
- native 的声音事件按需写入 `sfx` 或 `beats[].sound`；已有逐拍声音时镜级汇总让位。
  台词写 `lines[]`，由引擎追加音色与口型要求；dubbed 不注入这些环境音效字段。
- 画面基准、素材编号、连续性、播放速率和视频防字要求由引擎编译，作者无需手抄。
  视频防字只限制额外字幕、未经要求新增的文字与标识、新增水印，不禁止素材已有文字。
  具体素材职责及完整请求用 `gen-video --dry-run` 核对。

**示例一 · 连续动作**：

```json
{
  "camera": "侧向跟拍，保持全身和落脚区域可见",
  "video_prompt": "白刻向右跨过低矮木栏，落地后保持跑势离开画面",
  "video_prompt_en": "Bai Ke vaults the low wooden fence to the right and keeps running out of frame after landing.",
  "sfx": "落脚声接上连续跑步声"
}
```

结束时仍在奔跑，无需为了收尾另加停稳；镜长按这一个动作所需时间确定。

**示例二 · 情绪反转与希区柯克变焦**：

```json
{
  "camera": "镜头后退并同步变焦，保持林深的画面占比，办公室纵深随之拉伸",
  "video_prompt": "林深读到最后一行，搭在鼠标上的食指停在半空；笑意从眼角褪去，嘴角随后落下，目光仍停在屏幕上",
  "video_prompt_en": "As Lin Shen reads the final line, his index finger pauses above the mouse. The warmth leaves his eyes, then the corners of his mouth drop, his gaze still fixed on the screen."
}
```

静止是本镜有意安排的反应；空间变化由 `camera` 表达，不在正文再写一遍。

**示例三 · 升镜揭示与事件拍序**：

```json
{
  "camera": "镜头越过青瓦屋脊升起，逐渐展开水镇全景",
  "sketch": {"beats": [
    {"action": "一只狸花猫沿近处的瓦沟走过，尾巴在转身时划过屋脊"},
    {"action": "镜头越过屋脊后，晾在竹竿上的蓝布进入前景，随风鼓起"},
    {"action": "远处水镇与河道进入画面，一条乌篷船从画左驶入，涟漪向两岸展开"}
  ]},
  "sfx": "近处风声，远处摇橹水声"
}
```

这份拍序用于安排信息揭示，不代表固定三拍公式；正文可以省略，避免重复整条拍序。
没有明确卡点时保留事件顺序即可，分段格式交给引擎。

## 运镜词 → 引擎 Ken Burns 映射（kenburns 模式）

kenburns 模式引擎按镜号轮换四种运镜（此模式下 `camera` 字段只作标注，实际运镜由镜号决定）：
`slow push-in`（推近）/ `pan right`（右移）/ `pull-out`（拉远）/ `pan left`（左移）。
**dubbed/native 模式下 `camera` 字段会被引擎自动并入视频提示词**（「运镜：…」），
所以 camera 请写真实可执行的运镜语义（推近/环绕/跟拍/拉升），别写虚词。
