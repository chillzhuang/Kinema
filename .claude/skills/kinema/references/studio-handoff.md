# Studio 交互交接协议

这份协议用于所有“下一步需要用户在网页控制台操作”的节点。它不是一句提示语，而是
Agent 在停下等待用户操作前必须完成的动作。

## 何时触发

下一步包含以下任一操作时，先确保 Studio 已启动，再提示用户：

- 试听、选用或更换旁白/角色音色；
- 在候选宫格中选定设定图、分镜图、封面或其他版本；
- 在章节页审阅、批准、退回重做、标记弃用或填写镜级意见；
- 在项目页上传小说/剧本、查看改编结果或使用剧本工作台；
- 任何明确要求用户“打开 Studio / 项目页 / 章节页后点击”的操作。

如果只是让用户在当前对话里确认文案、授权出图或回答一个选择题，且后续不依赖网页，
不要为了形式启动 Studio。

## 固定顺序

1. 沿用当前任务的工作区、`KINEMA_*` 环境变量和存储后端；不要因为启动 Studio
   擅自切换 local/MySQL。命令从 `engine/` 目录执行。
   这里的工作区是仓库根 `project/` 数据目录，不是仓库根本身，也不是 `engine/`；
   从 `engine/` 启动可省略 `--workspace`，引擎会自动定位到仓库根 `project/`。
   如需显式传参，使用 `--workspace <仓库根>/project`；传仓库根或 `engine/` 也会被
   引擎归一到该目录。
2. 先查本工作区是否已有实例：

   ```bash
   python3 -m kinema studio --workspace <workspace-project-dir> --status
   ```

3. 如果状态是“未运行”，由 Agent 启动单实例服务。优先使用宿主提供的长驻终端会话执行
   下面的命令：命令本身不要加 `&`，让宿主立即返回会话 ID 和启动输出，但不要等待它退出，
   也不要把这条命令转给用户执行。端口默认 8787；不要重复启动，也不要用 `--restart`
   代替首次启动：

   ```bash
   python3 -m kinema studio --workspace <workspace-project-dir> --port 8787
   ```

   命令打印 `打开: http://...` 后即可交接，保留这个长驻会话，不要发送 Ctrl-C。
   如果宿主不支持长驻会话，才使用脱离后台方式，并在启动后再次执行 `--status` 轮询几秒：

   ```bash
   mkdir -p .studio_cache
   nohup python3 -m kinema studio --workspace <workspace-project-dir> --port 8787 \
     </dev/null > .studio_cache/studio-agent.log 2>&1 &
   ```

   已有实例直接复用 `--status` 返回的 URL；只有用户明确要求重启或端口确实失效时才使用
   `--restart`。
4. 先告诉用户控制台已经可用，再告诉用户唯一的下一步操作。交接信息必须包含：
   URL、项目 ID、章节 ID（如适用）、要进入的页面和要点击的动作。例如：

   ```text
   Studio 已启动：http://127.0.0.1:8787
   请打开「项目 → book_explainer → ch01 → 章节页」，在旁白卡片中试听并点击“使用这条”。
   完成后回复“已选好”，我再继续写入后续流程。
   ```

   默认只启动本地 Web 服务并给出可点击 URL，不擅自调用系统浏览器；用户明确要求打开浏览器
   时，再按宿主能力处理。
5. 启动失败或轮询仍拿不到 URL 时，不要只让用户自行排查。先报告启动输出或 `--status` 的
   实际结果；若使用了脱离后台方式，再附日志路径 `.studio_cache/studio-agent.log`，然后给出
   当前节点可用的 CLI 替代动作；不要假装网页已经可用。

## 退出与复用

Studio 是跨节点复用的本地控制台。完成一次交互后不要自动停止，后续节点继续用 `--status`
复用同一实例；只有用户要求停止，或任务结束并明确需要清理时才执行 `studio --stop`。
