# casebook · 判例集与交付前独立终检

> 两件事收在这一份：**判例集**（真实返工与用户点名沉淀成的裁决记录）与
> **交付前独立终检协议**（成片交付前的最后一道人审）。判例集的价值在于**可累积**：
> 方法论文档写"该怎么做"，判例记"哪次没这么做、赔了什么"——后者才拦得住重犯。

## 一、判例集

**三条元规则**（本节的宪法，改判例先读它）：

1. **编号一经发布永不重排、永不复用**——别处文档会引用 J-xx，重排等于全部失效。
   新判例只追加在表尾。
2. **准入门槛：真实发生过**。判例必须来自一次真实的返工、一次实测事故或一次用户
   点名——臆想的"可能会错"不收（那是方法论文档的事）。入表时写清项目/镜位。
3. **可以有意识地违反任何一条**，但必须在该镜 `shot_intent` 或 `decision add` 里
   写明理由——没有留痕的违例，下次会话会被当成漂移"修"回去。

| 编号 | 规则 | 判例（真实事故） | 自检问题 |
|---|---|---|---|

| J-02 | 人走得进去的一律 `scene add`，绝不登记成道具 | 「孢子宫殿」被登记进 props[]，套上物件转台版式，画成了一把蘑菇战锤 | 这个实体是"一个地方"还是"一件东西"？ |
| J-03 | `shots[].characters` 逐镜必填，空镜/群像写 `[]` | abyss ch01：缺省全挂＋全员外貌前置，分镜被画成「人物设定总表」 | 每一镜的出场表都显式写了吗？ |

| J-05 | 每镜必填 `shots[].scenes`，同景段共享环境连续性句 | 镜21：未声明取景地，夜戏中间被模型抽出一幅白天街头 | 相邻镜的取景地锚相交吗？（跳景处**不要**顺手补转场——那是用户的取舍） |

| J-07 | 一镜多人说话必须逐句 `shots[].lines[]`，绝不塞进一个 `narration` | 用户点名：对白写成一段 narration，两个角色共用一把嗓子，非常出戏 | 这一镜里开口的有几个人？ |
| J-15 | **同一个说话人的多句台词也要拆 `lines[]`——说一句显示一句** | 用户点名：玉简三句留言塞进一个 narration，字幕一次性全摊在屏幕上，"他们会发现你"这句收尾在念第一句时就被剧透；文本超行宽后按字数硬切，收尾引号被甩到下一行行首（`…说明我们失败了` / `」「不要继续飞升。」`）。字幕对单段镜只发一条事件、横跨整镜时长 | 这一镜的台词有几句？拆出的句数与 `sketch.beats` 的拍数对齐了吗？ |
| J-16 | **出完角色设定图必须比对「这是不是我要的那个人」，脸尤其要看** | 用户点名：`anime_xianxia` 的黑发白袍少年被画成版式样板那张女性面孔。根因不在措辞而在资产——当时的角色样板带具体人物形象，样板上的脸被模型当成了可复制的内容，职责声明逐维点名也只救回一部分。**资产侧已根治**：现行样板是每类一张去身份**简笔线稿**（`char_template.png`），线稿上没有身份内容可抄，版式职责由 `template_role` 职责声明单独钉死，长相条款只作兜底；脸走样时来源在文字侧（`appearance`/`silhouette`），这条自查照做 | 设定图上的人，性别/年龄/脸型与 `appearance` 对得上吗？不对时改的是 `silhouette`/`appearance` 的具体特征，还是又原地重滚了一次？ |

| J-11 | retake 一次只改一个变量 | 一次改三处再重投，出来还是不对时无法归因，只能继续抽卡烧钱 | 这次 retake 动了几处？ |
| J-12 | 提示词点名道具用设定集 `name` 措辞 | 措辞不符时设定图不挂载：写「面板」而注册名是「系统面板」，参考落空 | 本镜点名的道具措辞与注册名/keywords 一致吗？ |
| J-13 | 旁白不是必填件——剧情语态（sparse）对白与动作是主轴 | 用户点名：每建一个章节，几乎每镜都配了旁白——漫剧被写成了解说片；对白该进 `lines[]`/`speaker`，动作战斗该是纯画面镜 | 本片语态是哪档？旁白镜占比多少？哪几镜的旁白能改成对白或画面？ |
| J-17 | **`style_prompt` 只写媒介与质感，绝不写构图 / 机位景别 / 画面里有什么主体** | silence/ch01：前缀里多写了「超广角深空构图与极低地平线，人在画面中极小」。前缀被无差别拼进每一镜，于是 9 镜里 6 镜坍缩成同一个模板「低地平线 + 一个站着仰望的小人」——太空回望地球那镜凭空长出一名宇航员、该是纯深空空镜的一镜被画成山顶仰望且与收尾镜撞构图、危险感峰值镜的遮星黑影变成耀斑，一次废 5 张（¥1.5，占该章总花费 36%）。**加剧它的是验收方式**：首镜恰好本就是「低地平线 + 小人仰望」，`--only 1` 那张完美无缺，前缀的病一点没露，续跑完 8 张才发现。**刻意不做自动守卫**：46 个现有画风档里 11 个的前缀含「构图」二字（"清晰构图"/"电影海报级构图"是质感陈述不是构图指令），词表必然误伤；而本事故的前缀里景别词运镜词一个都没有、150 字也落在现有 28~158 的分布内，词表与长度阈值双双漏抓 | 前缀里每一句：**换一个镜头还成立吗**？三类必须清掉——① 构图与画幅位置（地平线高低/三分点/占画面几分之几/负空间在哪）② 机位与景别 ③ 主体的存在与尺度（「人在画面中极小」「一个背影」）。首镜验风格时：我挑的这一镜，是不是恰好和前缀里那句话长得一样？换一个纯空镜再验一张了吗？ |
| J-14 | 照抄范例而不是照抄清单——范例的字数量级就是产出的字数量级 | 用户点名「镜头设计与提示词还是有点低级」。全集群唯一一份完整字段范例（`references/storyboard.md` 标准示例）的 `video_prompt` 曾是 22 字，低于引擎自家地板；同期章节 `catquest/ch01` 均 27.0 字、`jiafang/ch01` 均 26.2 字，与范例同量级，而被手把手迭代过的 `chrome2/ch01` 均 353.9 字——**13 倍**。清单（五项必写/五层结构）当时已经写着，没拦住 | 我这一镜的写法是从哪儿抄来的？抄的那份自己达标吗？五层里有没有空着的层？ |

**怎么长新判例**：制作中发生返工或被用户点名时，先 `decision add` 留痕（当次会话
的义务），复盘时若它具有跨项目的普适性，再从 decisions 提炼进本表——两级沉淀，
decisions 记"这个项目怎么了"，判例集记"所有项目都别再这样"。

## 二、交付前独立终检协议

**什么时候跑**：成片通过节点⑤、准备 `deliver` 交付或发布之前，跑一次。它不替代
过程中的逐节点确认——它是**换一双干净的眼睛**做最后一遍整片检查。

**谁来跑**：派一个**全新上下文的 subagent**（不带制作过程记忆）做检查——制作者
自查自己的片子，确认偏差不可避免：你知道每一镜"想要什么"，所以你看到的是意图，
观众看到的才是画面。没有条件派 subagent 时，至少隔一个会话再查。

**机器底座先绿**：终检是人在机器绿灯之上的最后一双眼，四个零成本闸先跑完——
`lint`（分镜面）· `verify`（成片六项体检）· `consistency scan` + 人工判定（角色
跨镜）· `spec check`（平台规格）。机器红着就送终检，是拿人力干机器的活。

**六组检查项**（逐条过，每条给三态结论 `pass / fail / unverified`）：

| 组 | 查什么 |
|---|---|
| N 叙事 | 全片一句话意图兑现了吗；钩子是否在前 3s 落地；CTA 单一明确；每镜 `shot_intent` 的职责在成片里成立吗 |
| C 一致性 | 角色五官/发型/服装跨镜同一人；场景光位色温同景段延续；道具形制不漂移；音色与角色绑定零漂移 |
| R 节奏 | 换挡分布（超 30s 空窗有没有理由）；hero_moment 那一两镜真的立住了吗；有没有该剪的拖沓镜 |
| A 声画 | 音字一致（字幕逐字对配音）；情绪档生效了吗（不是白开水）；混音让路（BGM 不压人声）；停顿落点自然 |
| T 技术 | verify 六项全绿；字幕断行与安全区（各比例分别看）；比例构图（竖版主体与 UI 遮挡区）；片头片尾干净 |
| P 合规 | AI 生成披露就位；素材/音乐授权可溯；参考片及其抽帧未混入交付物；水印按约定打或不打 |

**四条纪律**：

1. **每条结论必须带证据**：镜号或时间码（「C2 fail：镜 7 约 00:41 处发色由黑变棕」），
   指不出位置的结论不算查过。
2. **禁全绿**：「整体不错」不算结论——没有镜号/时间码支撑的 pass 一律无效；为了
   让报告好看而放行的每一项，交付后都会变成公开的返工。一份零 fail 零 unverified
   的终检报告，首先该被终检。
3. **unverified 是合法结论**：查不了的（比如没有竖版投放就不查竖版安全区）写
   unverified 并说明，不许顺手写 pass。
4. **报告落盘再交付**：`project/<项目id>/plan/final-<章节id>.md`，并
   `decision add --chapter <项目>/<章节> --choice "终检通过/有保留通过" --why "…"` 留痕
   ——fail 项要么修掉重查，要么用户明示接受后带痕交付。
