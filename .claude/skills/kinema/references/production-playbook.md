# kinema 生产作业手册

> 仅在实际制作视频时读取。本文件保存完整节点细则、提示词纪律和既有判例；Skill 主文件只保留路由、铁律与执行状态机。

你是这条流水线的**指挥层**。你负责所有「需要智能」的环节（检索、文案、分镜、提示词），
把结果写进一个 `project.json`，再调用本仓库的执行引擎 `engine/`（`kinema` CLI）完成
生图、配音、字幕、图生视频、合成等机械环节。**画面比例**：横屏 16:9（默认）/ 竖屏 9:16 /
方形 1:1，可一次出多比例。**渲染模式**：不写 `motion` 时按内容定档（有对白 → native、全旁白 →
dubbed）；静图 kenburns（零视频成本）须显式写。**不含发布。**

本 skill 在集群里承担**双重角色**：① **流程真源**——所有 route / overlay 风格 Skill 都
Read 本文档拿节点工作流、铁律与 CLI（它们只覆写画风 DNA 与视觉生产方式）；
② **通用直达入口**——用户直接调用时，先走下方《画风解析链》定档再开工。

### Studio 交互闸

本手册任何地方只要下一步需要用户在 Studio 试听、点选、上传、审阅或进入导演台，
都必须先执行 [Studio 交互交接协议](studio-handoff.md)，由 Agent 自动启动或复用控制台，
确认 URL 后再把项目、章节和具体点击动作交给用户；不要只把网页地址或启动命令丢给用户。
仅在当前对话中确认文案、授权或选择，不依赖网页时，不启动 Studio。

集群一览（共享同一引擎与流程，只是绑定不同 profile）：
- 风格向：`kn-anime`（动漫总入口·十五大画风：现代新番默认/赛璐璐/吉卜力/新海诚/国漫仙侠/机甲/JOJO/美漫/像素/涂鸦/童话绘本/水墨…）
  · `kn-anime3d`（3D 总入口·五路线：国漫年番｜爱死机 CG｜写实数字人与宠物｜虚拟制片｜黑色写实）
  · `kn-cyberpunk`（赛博朋克）· `kn-clay`（粘土定格）· `kn-miniature`（微缩世界）
- 游戏画面：`kn-game`（游戏总入口·十一大风格：HD-2D/GBA/超任/暗黑像素/实况HUD/PS1低模/体素/等距CRPG/卡通渲染/视觉小说/街机——对话框叙事与实况双机制）
- 内容向：`kn-book`（图书说书/荐书：接微信读书官方接口选题取料）· `kn-explainer`（知识解说）· `kn-quote`（语录/治愈）
  · `kn-ranking`（榜单盘点）· `kn-storybook`（绘本故事）· `kn-showcase`（素材复用型解说：无角色，
  AI 生成一小组资产图跨镜复用拼接）
- 规划：`kinema-project`（项目化管理：项目/系列→章节→角色/总体设计，JSON 数据库 CRUD + 大屏）

## 画风解析链（与音色解析链、profile 三级覆盖同一范式：高优先级命中即停）

**⓪ 项目已绑定 → ① 上游已定 → ② 用户点名 → ③ 题材匹配 → ④ narration 兜底**

0. **项目已绑定 skill**：用户只报**项目名 / 编号**让你在某个已存在项目里创作时
   （"给猫剑奇谭写第一集""在 catquest 里继续"），先读该项目 `project.json` 的
   `skill` 字段——立项时已由画风确定性派生落库（网页新建项目 / `project new`）。
   **命中即直接按该 skill 开工，无需再点名画风、无需问用户**（`kn-anime`→读
   kn-anime 拿 DNA；`kinema`→本档）。这是最高优先级，让"报项目名即接着做"成立。
   单一真源是 `agent/manifest.json` 编译出的 Agent catalog（画风→归属 Skill）；
   可用 `python3 -m kinema agent route --project <项目id> --json` 查看理由与摘要。
1. **上游已定**：本文档被某个 kn-* 风格 skill 引用时（kn-anime/kn-game/kn-clay…
   自带选择协议或绑定 profile），画风已由该 skill 定档——**解析链到此为止，
   后面三级全部跳过**，本文档只供节点工作流、铁律与 CLI。
2. **用户点名**：直接调用本 skill 但话里带风格信号（"宫崎骏那种"/"像素风"/
   "粘土的"）——直接用对应档，不再询问。
3. **题材匹配**：直接调用且未点名——从需求里读出题材与质感诉求，按下表匹配
   最合适的画风档，并 Read 对应 skill 的 SKILL.md 拿画风 DNA 与分镜法则执行。
4. **兜底**：纯口播/新闻信息/无画风诉求——本 skill 的 `narration` 档。

| 手作/定格/玩具（粘土/高达/手办/积木） | `kn-clay` | — |
| 说书/荐书/拆书/书评/书单号/图书带货/微信读书 | `kn-book` | 官方 Agent Gateway 取料（热门划线=金句榜），说书三段式 |

| 纯口播/新闻信息/无画风诉求 | 本 skill `narration` 档 | 集群兜底 |

- **匹配细则（仅第③级生效）**：题材强信号 > 内容形态；两档难分高下时一句话
  给出推荐与理由请用户拍板（整条解析链仅此一种情况阻塞，其余直接开工）。
- **执行规则（②③级路由后）**：完全遵循目标 skill 的画风 DNA、分镜法则、声音
  设计与 profile——本 skill 的通用流程（节点/铁律/CLI）继续适用，两者叠加：
  genre skill 管"长什么样"，本 skill 管"怎么生产"。
- 无论哪级定档，立项汇报里向用户交代一句选风结果与理由（「按题材选了 X 画风」），
  画风经 `project.style_prompt` 快照全片统一。

## 配置与风格档（不写死模型）

模型不在代码里写死，全在 `config/models.yaml`：`providers`（厂商**别名**注册表，密钥走 env；
`impl` 字段指向适配器，同厂新模型=加别名零代码）+ **`defaults.providers`（全局默认别名总
入口，换厂商只改这一行）** + `profiles`（命名风格档，只在偏离默认时写 provider；画风前缀
双语 `style_prefix`/`style_prefix_en`，英文优先模型自动选用）。换模型/调风格=改 YAML。
- 项目整体风格：project.json 的 `"profile"`（如 narration/anime/explainer），或 CLI `--profile` 覆盖。
- 逐镜可用 `shots[].profile` 覆盖 → 一个项目可混合多种风格。
- 特效：profile 自带默认特效，或 project.json 的 `"effects": [...]` 覆盖（rain/vignette/film_grain/hud/scanlines）。

## 铁律

0. **产物必须落进项目库，绝不污染文件系统（强约定）**：所有生成物（project.json/图片/配音/
   字幕/音乐/成片/中间文件）一律放在项目库 `project/<项目id>/` 内。**未指定项目时默认用
   `project/demo` 工程**。**绝不把文件写到 `/tmp`、仓库根或其他随意位置。** 标准做法：
   `kinema project new`（或用现有项目）→ `kinema chapter new <项目> --title ...`
   → `kinema run --chapter <项目>/<章节>`。禁止 `run --project /tmp/xxx.json` 这类散落写法。
   工作区数据根目录默认是仓库根 `project/`（可用 `--workspace` / `KINEMA_WORKSPACE`
   覆盖；从 `engine/` 启动也不能落到 `engine/project/`）。local 与 mysql 只改变持久化
   后端，始终共用这个数据根。
1. **默认逐步确认·多道节点（除非 `--auto`）**：① 文案+分镜 → **①.5 设定单+设定图** → *(①.7 3D 导演编排 ·
   可选)* → ② 生图(先首镜) → **②.7 封面（系列+本章，Studio 卡片图源，生图过审后必做）** → ③ 配音 → ④ 合成 → **④.5 全片样片节奏审(animatic)** → ⑤ 动态化。
   **每道节点**：产物落盘 → 让用户开大屏查看（`kinema studio`）→ **停下等确认** → 才进下一步。绝不一口气跑到底（除非 `--auto`）。
   **并发提速（默认已开，只有 Seedance 例外）**：`project refs` / `gen-image` / `tts`
   都支持 `--concurrency N`（缺省 4，上限 16，`KINEMA_CONCURRENCY` 可固化）——
   十几张设定图串着出要等很久，并发是这条链路上最直接的提速。**给用户跑批量时
   主动加 `--concurrency 8`**（设定图/分镜图/配音都适用）。
   **`gen-video` 缺省恒串行、显式 `--concurrency` 才并发**：Seedance 按秒计费
   （单价见 config/models.yaml，4K 翻倍），静默并发等于同时下多张高价订单；
   它不吃 KINEMA_CONCURRENCY 环境变量，4K 档点了并发也压回串行，parallel 层重试恒关。
   跑批期间引擎每 3 秒报一次进度「已完成 n/总数 · 已用时 · 正在跑哪几件」，
   不会静默等待——**跑批量时不要以为卡住了就中断**，看心跳行即可。
   失败不再拖垮整批：某张炸了其余照常登记，收尾点名未成的，重跑同一条命令
   会自动跳过已成功的（瞬时错误引擎已自动重试，业务错误不重试以免重复计费）。

   **六条防烧钱铁律**：
   - **自审发现的问题一律不自动重生**：`verify` / `consistency` / lint 报出的每一条
     都是**复核清单**，不是重生指令。片段已经出来了，重投一次就是再付一次钱，
     而自审本身会误报——`voice_text_drift` 的 ASR 转写把轻声台词听成空、把「零七」
     写成「07」，`consistency` 只看一帧代表帧，`scene_jump` 只报直切事实。
     **结论只落成那一镜的审阅意见**（`review set --shots N --stage clip --note …`，
     写进该镜分镜卡的「审阅意见」行），**重不重生由用户裁决**。意见按镜写具体，
     别把一句全片总结复制到每一张卡上。
   - 走 Seedance（dubbed/native）前**必须先 `gen-video --dry-run` 列出每镜完整提示词 + 成本预估供用户审阅**，
     通过才真跑（绝不黑盒直接调 API 烧钱）。
     **秒级规划先行（kinema-sketchboard「规划优先」铁律〇）**：每个要动态化的镜先有
     「第几秒干嘛」的秒级运动规划——首选写 `shots[].sketch.beats`（**无板也生效**，引擎自动
     编译分段时间轴注入提示词，零成本）；重点镜再花 0.3 元出简笔板（缺省档板在盘即随请求
     附发；只有衔接章里要让某镜走参考孤岛才需 `sketch ref --shots N --state on`）；两者都没有的镜，
     `video_prompt` 必须自带先后次序的详细分段（起势→推进→收束），绝不发一句笼统散文。
     dry-run 逐镜行的「参考图=简笔分镜板 / 分段时间轴(无板)」标记就是核对位。
     **镜间连贯双保险**：要求相邻镜连续承接时，先写文字咬合——上一镜 `end_state` +
     本镜 `entry_state`（引擎编译为「开场承接：」句，lint `entry_continuity` 查单侧缺失）；
     要像素级承接再开章级 `tail_relay: true`（上一镜片段真实末帧作下一镜参考图，与板/
     设定图/时间轴同发，强制串行，详见 `docs/agents/tail-relay.md`）。首次启用按
     「首镜试跑」纪律先验一镜再放全章。
   - 生图先 `gen-image --only <首镜id>,<一个纯空镜id>` 出**两张结构最不同的**确认风格/
     一致性，OK 再续跑其余镜。**只出首镜一张不够**——首镜常与画风前缀里的隐性构图令
     恰好一致，验不出前缀有病（判据见铁律2⓪「首镜验风格要挑对镜」）。
   - **草稿两段式**：动态化前先 `animatic` 出全片 Ken Burns 样片过**节奏审**（零视频成本），
     通过后正式 `gen-video --approved-only`——**只烧分镜图已批准(done)的镜**。
   - **就绪度节点（引擎自动）**：设定图不齐的镜 `gen-video` 逐镜拦截（先 `project refs` 补齐）。
   - **4K 二次授权**：默认按 config 档位（1080p）生成；用户口头要 4K 时先
     `--resolution 4k --dry-run` 出 **4K 档报价**（总价≈2×1080p·并发独享 1 会排队）给用户，
     **用户明确同意后**才加 `--resolution 4k --yes` 正式生成——引擎会硬拦无 `--yes` 的 4K，
     这是刻意的双保险，**绝不替用户补 `--yes`**。
2. **设定集优先（强制·一致性根基）+ 动作随剧情变化**：

   ⓪ **媒介统一铁律（画风的第一维，先于一切构图与色彩）**：一个项目**只许有一种媒介**
   ——2D 手绘 / 3D CG 渲染 / 实拍摄影，三选一，选定后**角色设定图、场景图、道具图、
   分镜图、封面、扩展设定图全部同媒介**，绝不允许「设定图是 2D、成片是 3D」。
   - **媒介的唯一真源 = `project.style_prompt`（立项时由 profile 的 `style_prefix` 快照）**。
     写分镜、出设定图、出封面三条路径都只读它，别在任何一处另写媒介词。
   - **样板图只给版面骨架，绝不给画风、更绝不给脸**：`project refs` 会给角色/道具设定图各垫
     一张内置版式蓝图（`engine/kinema/assets/blueprints/` 的 `char_template.png` 16:9 与
     `prop_template.png` 1:1），引擎已注入职责声明（`sheets.template_role`）
     声明「只准参考布局——分区/位置/比例；画风、媒介、人物物件、**样板上那个人的脸型/五官/
     发型/发色/性别/年龄感/身材比例**一律无关，且必须与本项目其余产出同媒介」。
     蓝图本身是**简笔线稿**（无脸无发无服装的中性示意），画风与身份维度上
     没有可抄的内容；长相条款是换回带脸样板时的兜底，不是当前资产的现状描述。
   - **★出完角色设定图仍要比对一次「这是不是我要的那个人」**（脸是最容易走样的一维，
     只是走样的来源已从样板转回文字）：**发现脸不对不要只改 `appearance` 就重滚**，
     那是同一口井里再打一次水；把性别/年龄/脸型的具体特征写进 `character set --silhouette`
     （会拼进设定图提示词），或在 `--appearance` 里直接点名要回避的方向
     （如「男性面部结构，下颌线明确，眉骨略高，绝非女性面孔」）。
     **但这条声明是有前提的——它把画风裁决权交还给「开头的风格描述」，所以
     `style_prompt` 里必须真的有媒介词**；媒介缺笔时模型只能从样板图上抄媒介，
     设定图就会被带成样板那档画风（cyberpunk 实例：设定图 2D 动漫、分镜图写实 3D、
     封面 2D 插画，同一个项目三种媒介）。
   - **★同一次核对里量一眼身体比例**（引擎验不了这一维，只能人看）：全身立像取头顶
     到脚底的中点，**裆部应落在中点或略高于中点**；落到中点以下就是腿短，观感立刻
     廉价。比例契约（八头身逐段高度）由 `sheets.figure_proportions` 注入，**写实档
     不垫版式蓝图、比例全靠这段文字**，是最容易被模型按训练集均值拉偏的一维。
     发现腿短别改 `appearance`——那里写身高体型会与比例契约抢同一件事；
     照旧 `review set --stage image --state retake` 重出，连着两次仍偏就报出来，
     该改的是引擎侧的契约不是这一次抽卡。
   - **★反向同样是铁律：`style_prompt` 只写媒介与质感，绝不写构图 / 机位景别 / 画面里
     有什么主体**——前缀被无差别拼进每一镜，写一句构图＝给全片下同一条构图令，
     各不相同的 `image_prompt` 会一起坍缩成同一张图（silence/ch01 废掉 5 张）。
     落笔自问：**「这句话换一个镜头还成立吗？」**不成立的就不该待在前缀里。
     **本条没有自动守卫、`lint` 也抓不到**（词表既误伤"清晰构图"这类质感陈述、又漏抓
     真事故）——完整解剖与判例详 → references/casebook.md 「J-17」。
   - **开工前先验两句**：`project new` 之后看一眼 `project.style_prompt`——① 开头有没有
     媒介词（2D 手绘 / 赛璐璐 / 写实 3D CG / 实拍摄影…）；② 逐句读一遍，凡「换个镜头
     就不成立」的句子当场删掉。**缺媒介就补、掺构图就删**——
     `project set <项目> --style-prompt "<媒介词>，<原前缀>"`，或改 `config/models.yaml`
     该 profile 的 `style_prefix`（全局生效，推荐）。这是一次两秒钟的检查，
     省掉的是整个项目重出图的钱。
   - **★首镜验风格要挑对镜**：`--only 1` 通过**不等于**前缀干净——首镜常与前缀里的隐性
     构图令恰好一致（那张图完美、病一点不露，续跑完整章才发现）。首验出**两张结构差异
     最大的镜**，其中一张是没有人、没有地面的纯空镜（J-17）。
   - **2D 档的连带纪律**：`shots[].lens` 一律留空（手绘没有物理镜头，写 `85mm 浅景深`
     会把模型往摄影写实拽，且引擎的「摄影字段地板」会把它自动灌进每一镜）；
     3D/实拍档照常写焦段。

   **版式靠内置版式蓝图垫，不靠每次赌提示词**（`engine/kinema/assets/blueprints/`，
   与简笔分镜板同一个药方）：角色与道具**每类一张简笔线稿样板**——角色
   `char_template.png`（16:9，三区两视）、道具 `prop_template.png`（1:1，结构三视式，
   `sheets.PROP_LAYOUTS` 仅此一式）。线稿上没有画风、身份或材质可抄，
   「版式是不变量、内容是变量」由 `template_role` 职责声明钉死，单张即成立。
   `project refs` 生成时自动把样板垫在参考图最前并注入职责声明
   「**只准参考布局**——分区/位置/比例；人物/物件/配色/画风/媒介绝不复制」。
   **场景刻意没有样板**——它是单幅环境
   key art，没有分区结构可教，垫具体空间只会污染陈设与光线。契约改了要重做样板，
   方法见 `engine/kinema/assets/README.md`（手工定稿或用契约反推生成，样板与契约同源）。

   ① **项目创建后必须先出「设定集」**（除非用户明确要跳过）：**角色设定图**（动画工业
      model sheet 定稿版式，横版 16:9 三区两视——左区约 40% 宽为锁骨以上正面肖像大特写，
      中区/右区各约 30% 宽为正面与背面全身立像，同地平线等高等比）、**场景设定图**、
      **道具/武器设定图**，统一存 `project/<项目>/assets/refs/`。
      **版面纪律由引擎注入，不由你手写**——三区分区与两视全身、全身像无条件空手
      （武器与随身物件归独立的道具/武器设定图）、无色板无细节格、
      中性表情、**整张纯图片不出任何文字**这些条款的单一真源是
      `sheets.char_rules`/`char_tail` 与 `prop_rules`；`project refs`、`refine --asset` 局改、
      灯箱重生三条路径共用同一份，要改版式改那里，不在提示词里另写一套。
      建法：`character add <项目> --name X --outfit ... --hair ... --weapon ...` → `prop add <项目> --name Y [--kind weapon]` → **`scene add <项目> --name Z --keyword 别名`**（取景地；
      **人走得进去的一律用它，绝不登记成道具**——道具是结构三视物件版式，画不出「一个地方」）
      → `project set <项目> --scene "一句话场景"` → **`project refs <项目>`**（生成全部设定图并回填）。
      之后 `chapter new` 自动继承设定集，**场景图与出场角色图每镜强制参考**（引擎 `design_refs`；角色缺省=全部角色全挂）；
      **道具设定图 = 本镜 image_prompt/narration 里点名命中的道具（按 `name`/`keywords` 自动挂载）∪ 显式 `shots[].props`**——
      在提示词里用设定集 `name` 措辞点名道具（或给道具配 `keywords`）即自动锁其设定图、跨镜一致；措辞不符/重名时用 `shots[].props` 显式兜底。
      **`shots[].characters` 逐镜点名出场角色（写分镜时必填的纪律，空列表 `[]`=明确无人出场）**：
      设定图挂载与角色文字锚都按它取材——缺省(None)时引擎按 name/keywords 文本命中推断，
      零命中的镜在**长阵容项目**（长篇改编几十个角色）会直接弃文字锚并警告；空镜/群像镜写 `[]`，
      否则设定图缺省全挂+全员外貌前置会把分镜画成「人物设定总表」（abyss ch01 实例）。
      引擎对设定图在场的角色只留绑定句（不复述外貌），并自动注入单帧剧情契约/设定图参考契约/防设定表地板。
      **怪物/灵体/兽类等非人实体只要登记在 `characters[]` 就同样要点名进出场表**——不点名=外貌锚不进提示词，
      「无毛无眼石膏质感的灰噬」会被画成有眼黑狼；正文只写了实体名（如「三只灰噬」）时尤其要点名，
      名字本身不含任何外貌信息。
      **跳过设定集**：`project set <项目> --skip-design`（或用户明说"跳过设定集"）→ 退回"首镜出图作固定参考(锚定)"。
   ② 各镜 `image_prompt` **只写这一镜不同的动作/姿态/表情/机位**，**不重复**外貌与场景（设定图+引擎已带）；
      对话有表演，**每镜动作都要不同**（捋须/指点/仰头/抱头/回眸…），切忌千篇一律、人物僵住。镜头可换角度/景别，不换地点。
      ⚠️ 无设定集时才可选 `scene_ref_lock` 首镜强锚（会复刻姿势，仅静态场景用）。
   ③ **资产血缘（引擎自动追踪）**：每镜生成时登记所参考设定图的指纹。`refs --force`
      重生设定图后**下游分镜自动标过期**（未锁定的置 retake 下次自动重生；已通过锁定的只挂
      标记等人裁决）；`lineage status <项目>` 查明细，`lineage mark` 手动传播。
      **跨项目复用**（IP 连载）：`assets list` 看全局资产库；
      `assets import <目标项目> --from <源项目> --name <角色>` 连设定图与在用音色档案一起搬。
3. **定音色（声线描述 → 定制立档 → 启用，全系列零漂移）**：每个说话人写 `voice_prompt`
   （**六槽位 40~80 字**：性别年龄段/音区明暗/音质质感/语速节奏/口音吐字/气质，不写情绪词，
   槽位表与范例见 references/voice-casting.md）——角色 `character add --voice-prompt "<声线描述>"`
   建档即定制立档（`character set --voice-prompt` 重新定制），旁白
   `voice custom --narrator --prompt "<声线描述>" --adopt 1`；引擎**自动同步全部章节**，各镜
   `shots[].speaker` 只填角色名。真发前 `tts`/`gen-video`/`score`/`run` 逐个点名未选角的说话人。
   模版音色是显式例外：`voice audition` → `voice use --no N`（官方固定音色，无声线描述可发给视频模型）。
   选过的每一把各留一条**音色档案**，可换回、有分镜引用则删不掉；换音色自动传播过期。
   详 → references/voice-casting.md

4. **先跑通再优化**：不确定时先 `--mock` 零成本看链路结构，确认后再换真实 provider（需 key、产生费用）。
5. **画面安全区（按目标比例）+ 字幕后置烧录**：主体居中、字幕落底部安全区之上
   （引擎按各比例画布分别排版）。**音字一致铁律：有旁白的镜字幕逐字取 narration（配音念什么字幕写什么）
   ，caption 只给无旁白的纯画面镜补位**。默认横屏 16:9；竖屏/方形用
   `--aspect` / `--both` / `--aspects` 控制，`image_prompt` 的构图标注要与主比例一致
   （见 references/storyboard.md）。**字幕永远不进画面**：分镜图与视频本体都是干净画面
   （引擎已给**图像与视频两侧**提示词都加防字地板，作者写的 `negative_prompt` 在前、地板在后；
   自己已写「字幕/subtitle」则不重复注入。只有画面里本来就该有字的两档 `game_sim`(HUD) · `explainer`(信息图)
   在 models.yaml 写 `image.image_text_floor: false` 关掉），
   字幕由合成段按 profile 的 `subtitle` 样式烧录——
   样式随画风换装（逐画风 `subtitle` 块见 models.yaml），游戏/对白向可用 `bubble` 头顶气泡
   （对白进气泡、旁白退底部，`shots[].bubble_pos` 标注左右落点）或 `dialogue_box`
   游戏框；单项目覆盖：project 顶层 `"subtitle": {"mode": "bubble"}`。
6. 联网检索用 WebSearch，抽取**具体数字/案例/反常识事实**塞进钩子与痛点，制造信息增量。
7. **审阅闭环（状态机 × 版本栈，防烧钱的制度化）**：每次生成后产物自动落「**待审**」，
   节点审完让用户逐镜表态再进下一步：
   ```bash
   python3 -m kinema review list --chapter <项目>/<章节>                      # 审阅看板
   python3 -m kinema review set  --chapter <项目>/<章节> --shots 1,3 --stage image --state done
   python3 -m kinema review set  --chapter <项目>/<章节> --shots 2 --stage image --state retake --note "构图偏左"
   python3 -m kinema review set  --chapter <项目>/<章节> --shots 5 --state omt --note "节奏拖"   # 弃用整镜
   ```
   - **done=通过即锁定**：`--force` 也不会覆盖（要重生先置 retake）——已确认的钱不再烧。
   - **retake=打回重做**：下次运行该阶段自动强制重生该镜，旧版**自动归档进版本栈**；
     `--note` 意见务必写具体（后续会编译进该镜下一版提示词）。**打回/重生前必须先读该镜
     `shots[].comments` 里未删除的锚定改造意见**（Studio 灯箱钉点），带九宫格方位汇总并入
     `--note`——与 Studio 分镜卡「重新生成」的自动携带同口径（引擎 `actions._regen_note`），
     意见不落空。
   - **omt=弃用**：整镜退出时间轴/字幕/成片（恢复：`--stage shot --state todo`）。
   - 版本栈：`versions list --chapter ...` 看谱系；`versions rollback --shot N --stage image --to 1` 回滚
     （当前版先归档，谱系完整；回滚后重跑 assemble --force 生效）。
   - **局部改造（只改这一处，第四种迭代手段）**：整图满意、只有一处不对时，
     不要整镜重roll——框选区域+指令让图像模型编辑重生：
     `refine --chapter <项目>/<章节> --shot N --rect "x,y,w,h" --note "把剑柄改成龙纹"`
     （rect 为 0~1 相对值；旧版自动归档可回滚）。**Studio 分镜卡点开图进检查器灯箱：提意见 / 框选局部改造 / 整镜重生成 / 下载原图；
     卡上「重新生成」一键重跑本镜**。设定图同理：`refine --id <项目> --asset character:名|scene|prop:名
     --note "..."`——改完下游分镜血缘自动传播（未锁定置重做）。
   - **配额经济与 retake 裁决（拿到一版产物后，先分档再动手）**：重生成是要花钱的，
     "不太满意"不等于"重投"。看到一张图/一段视频，先把它判进下面**五档之一**，
     每档只有一个对应动作，别越档操作：

     | 档 | 判据（一句话） | 动作 | 花钱 |
     |---|---|---|---|
     | **留用** | 达到"能用"，缺点观众不会注意 | `review set --state done` 锁定 | 零 |
     | **后期修** | 整体对，只有**一处局部**不对（道具颜色/一个纹样/背景一个物件） | `refine --rect` 局部改造 | 少（一次图像编辑） |
     | **剪** | 这镜本身没问题，但**片子不需要它**（节奏拖/信息重复） | `review set --state omt` 弃镜 | 零（还省了下游钱） |
     | **重投** | 构图/姿态/表情整体不对，但**提示词本身没写错**（纯抽卡没抽好） | `review set --state retake` + 重跑该阶段 | 一次同价重生 |
     | **重写** | 出来的东西说明**提示词写错了**（模型理解与你想的不是一回事） | 改 `image_prompt`（全片级用 `batch edit`）再 retake | 一次重生 + 你的时间 |

     判档口诀：**「只有一处不对 → 修；整体不对但词没错 → 投；模型理解错了 → 重写；
     不需要 → 剪；其余 → 留用。」** 拿不准时默认**留用**，等全片 `animatic` 看完再回头判——
     单镜盯着看永远都有毛病，放进片子里多半没人注意。
   - **一次只改一个变量**（本条是配额经济里最省钱的一条，也最常被违反）：
     retake 时**只动一处**——要么改构图，要么改光线，要么改姿态，**绝不一次全改**。
     一次改三处再重投，出来若还是不对，你无法知道是哪一处的锅，只能继续抽卡烧钱；
     一次一变量，每次重投都是一条确定的信息。同理：`--note` 意见写**一句具体的**
     （"人物右移到三分线"），不写"再好看一点"这种没有可执行动作的话。
     连续两次 retake 仍不对 = **提示词的问题，不是抽卡的问题**，停手回去改 `image_prompt`
     （或用 `decision add` 记下这条路走不通，别下次会话再撞一遍）。
8. **跨镜批量编辑（语义编译是你的职责）**：用户提出「把所有镜头改成夜晚 / 全片换发色」这类
   全片级修改时，**不要逐镜手改 JSON**——把自然语言编译成「字段 + 操作」交引擎确定性执行：
   ```bash
   python3 -m kinema batch edit --chapter <项目>/<章节> --field image_prompt --replace "白天=>夜晚"
   python3 -m kinema batch edit --chapter <项目>/<章节> --shots 2,5 --field video_prompt --append "，镜头缓慢推近"
   python3 -m kinema batch log  --chapter <项目>/<章节>     # 操作日志（留痕）
   python3 -m kinema batch undo --chapter <项目>/<章节>     # 撤销最近一次（还原字段+审阅状态）
   ```
   操作四选一：`--set` 整替 / `--append` 追加 / `--prepend` 前置 / `--replace "旧=>新"` 子串替换。
   **锁定(done)镜默认保护跳过**（`--include-locked` 才纳入）；提示词类字段改完**自动置 retake**
   （`--note` 意见编译进下一版提示词，旧版归档进版本栈可回滚；`--no-retake` 只改文案不触发重生）。
9. **文字先行 · 图片留空（长文本链路的默认档）**：源头是**一整本书 / 一整个系列**时——
   用户上传小说剧本走节点①.0 改编，或走 `kinema-novel` 让你自己写——**先把全部文字
   工作一次做完，一张图都不生成**：世界观宪法 → 设定单（角色/道具/场景的**文字字段**）→
   分集 → 逐集分镜（`image_prompt`/`image_prompt_en` 照样写全写好）。
   **写提示词 ≠ 出图**：提示词是文字资产，写进 JSON 零成本；`characters[].sheet` /
   `props[].sheet` / `scenes[].sheet` / `scene_ref` / `shots[].image` **空着就是本档的正常
   状态，不是"没做完"**——别看到空字段就顺手补一发生成。
   - **文字期禁跑**（一条都不许，用户说了 `--auto` 在本档同样不解禁）：`project refs` /
     `gen-image` / `gen-video` / `cover` / `refine` / `run`。
   - **`--mock` 一并禁**：mock 会把占位图落进 `sheet`/`image`，「哪些还没出图」当场就看不
     出来了，真要出图时还得先辨认哪些是占位——省下的那点链路验证价值远不抵这笔账。
     要验链路，等真出图那一批一起验。
   - **文字全部落盘后，出一张《出图就绪表》交给用户，然后停下**（自己 Read project.json
     与各章节 json 逐项数，别估）：待出角色设定图 N 张（`sheet` 为空的）/ 道具 M / 场景 K /
     逐章待出分镜图数（`shots[].image` 为空的），乘 `config/models.yaml` 里该 profile 的
     `price_per_image` 报出总价量级，并说明「先出哪一批最划算」的建议。
   - **只有用户明确下令**（"出图" / "生成设定图" / "开始生图" / "先把这三个角色出了"）
     **才动手**，且照旧走铁律1 的防烧钱纪律：**先设定图、后分镜图，分镜图先首镜确认**。
     用户没点范围时**默认只出设定图那一批**，绝不顺手把几十上百镜分镜图一起烧掉。
   - **例外**：单条视频（一个主题一条片）不走本档——那是节点①→①.5→②的常规逐门流程，
     一集十来镜，逐门停下确认的粒度本来就够细。

## 执行引擎位置与命令

引擎在 `engine/`。在 `engine/` 目录下运行（无需安装，零依赖即可跑 mock 与合成）：

```bash
cd engine
python3 -m kinema doctor                                    # 自检
# 逐节点（默认工作流，每步停下确认）：
python3 -m kinema gen-image --chapter demo/<章节> [--mock] [--force]   # 节点②生图（锁场景+首镜锚定）
python3 -m kinema tts       --chapter demo/<章节> [--mock] [--force] [--only 1,3]  # 节点③配音（speaker 固定音色）
                                                                          # --only=只配点名的镜（native 混烧常用）
python3 -m kinema score     --chapter demo/<章节> --dry-run            # 节点③**并列路线**（章节 audio_mode: scored）：整章人声+配乐+
                                                                          # 音效一次演出并混好；走这条不跑 tts 不配 BGM，剧本按
                                                                          # **kn-audio SKILL 第四节**写。--dry-run 零成本看分段与报价
```

所有阶段命令都支持 `--profile` 覆盖风格档、`--mock` 离线跑、`--chapter 项目/章节` 定位视频（也可 `--project <文件>`，
但产物须落 project/ 内）。

**画面比例**：默认横屏 16:9。`run`/`gen-image`/`compose` 支持：`--aspect 9:16`（竖屏）、
`--both`（竖屏+横屏都出）、`--aspects 9:16,1:1`（自定义）。默认出一套主比例图、其余用 Ken Burns
重构取景；要每个比例单独出图（画质最佳、成本翻倍）加 `--image-per-aspect`。

> **比例只认用户显式指定（判例）**：用户没点名比例就恒 16:9 横屏建项——目标平台不构成
> 改比例依据，「投抖音」说的是发布去向不是画幅，猜成竖屏就是替用户做了没授权的决定
> （lastcar 实案：平台词诱导建成 9:16，后按 `--both` 双出时 16:9 成片由竖图裁切、构图全毁）。
> 竖屏/方形必须来自用户原话（「竖屏」「9:16」「竖版」），拿不准就问，不猜。
> 多比例双出同理是显式动作：`--both` 会用主比例那套图裁切出另一比例，主图与目标比例
> 相差 90° 时先确认用户接受裁切或改用 `--image-per-aspect`。

**三种渲染模式（`motion`，适配所有 profile / skill；CLI 加对应开关，或 project 顶层 `motion`）**：

| 模式 | 开关 | 画面 | 声音 | 适用 |
|---|---|---|---|---|
| **`kenburns`** | `--kenburns`（须显式，不作缺省） | 静图 Ken Burns 运镜（零视频成本） | 我们的固定音色 TTS + BGM | 语录/知识/绘本，省钱先验 |
| **`dubbed`** | `--dubbed` | Seedance 图生视频（真动态） | **成片主音轨=我们的固定音色配音**（音色 100% 保真；整段配音同时作对口型参考喂给模型，片段里模型重演的人声不进成片）+ BGM；底片出齐后缺省自动**口型精修**（视频改口型服务按最终配音重绘对白镜口型，`--no-lipsync` 关；换音色只需 `tts --force → lipsync → assemble`，底片零重生） | ★解说型 / 对音色绝对一致有硬要求的内容 |
| **`native`** | `--native` | Seedance 图生视频 | **Seedance 原生音画**（口型/情绪/呼吸与画面同源一次生成 + 音效氛围；音色靠**音色锚定**跨镜稳定——声区跟随非复刻）；**缺省不烧我们的 TTS**——`assemble --burn-voice` 或章节 `native_voiceover: true` 显式开混烧（TTS 上主轨；原生音轨占背景床槽位，只在旁白镜窗口压低让路、对白镜窗口原电平直通） | ★写实剧情片首选：表演可信度最高；旁白要恒定音色时叠混烧（对白原生+旁白固定音色，两头兼得） |

- **`gen-video` 的模式收口**：章节从未写 `motion` 时按内容定档并播报——任一正镜有对白落
  **native**，全旁白/无词落 **dubbed**，scored 落 native（整轨人声与配音参考音互斥）；真发把
  表态写进章节，dry-run/预览只作用于本次。显式
  `motion: kenburns` 跑 `gen-video` 直接拒发——该模式合成按分镜图渲染，片段不参与出片。
- 需 `ARK_API_KEY`（dubbed/native 走 Seedance 2.0）。dubbed 会先跑固定音色 TTS 再喂给 Seedance；native 缺省跳过 TTS。
- **native 配音混烧（要音色统一又要保留模型音效时用）**：先给点名的镜跑 `tts`（逐镜挑着配用
  `tts --only 1,3`），再 **`assemble --burn-voice` 显式开混烧**（要常开就写章节
  `native_voiceover: true`）——TTS 上主轨 0dB · 原生音轨占背景床槽位：旁白镜窗口内降
  `NATIVE_BED_GAIN` 并让路 EQ、对白镜窗口原电平直通（那里它就是主人声），sidechain
  闪避照旧整轨挂（由旁白轨驱动，对白窗口里旁白本就是静音）。**缺省不烧**：native 片段自带模型原生人声，配音在盘也不自动叠
  （叠上=同一句话两个人说）。没配音的镜台词仍由模型原生自配，引擎按窗口占静音位、绝不错位。
  **native 下 tts 不改 `dur`**（那是 Seedance 计费秒数）。
  **混烧的声源按镜分治**：旁白/无词镜按闭声出演编译（闭唇、锚定不附发）、TTS 上
  主轨；**对白镜由模型原生发声、锚定照常附发**——旁白轨对对白镜恒插静音，
  `tts` 也不给对白镜合成。同一章内角色恒是模型声、旁白恒是固定音色。
  **混烧要在 gen-video 之前定**：旁白镜先出了片才开混烧＝旧片段是按讲述稿生成的，
  同一段两个人声（背景床压不住不重叠的第二遍），**assemble 对这些镜直接拒合成**并给
  两条出路（retake 重生 / 本次不烧）。⚠ 闭声出演**没有确定性**：同一闭声稿
  两发一守一破——assemble 另有旁白镜输出侧人声探测点名试听。对白镜别夹旁白句
  （lint `burn_mixed_narration`：那几句会由模型代声、与烧录旁白不同源，挪进
  纯旁白镜）。「完全替换原声」用 dubbed——但 dubbed 只用于全旁白解说章：
  对白上镜的烧录口型必然与配音时间轴失配（lint `dubbed_dialogue`），
  对白内容一律 native + 锚定。
- **缺省档=逐镜全能参考、一镜一片（native）**：分镜图+简笔板（在盘即附）+
  角色/场景/道具设定图（≤6·角色优先）全作参考图，配运镜词与分段时间轴
  生成一镜、**不发首/末帧**；合成时镜间**直接拼接**不加特效——要过渡自己插
  转场镜。dubbed 参考媒体同附板+设定图。
- **首帧锚定=显式 opt-in、仅 native**：章级 `anchor_frame: true`（或镜级
  `shots[].anchor_frame: true` / `--anchor-frame`）。分镜图以 `role=first_frame`
  **硬锁片段第 0 帧、不发末帧、镜间仍硬切**。用它的理由只有一个：缺省的全能参考
  只把分镜图当参考图，模型据它调和出开头几帧，**人工审过的那一帧并不是成片首帧**。
  **代价与衔接同**：设定图、简笔板、尾帧接力三条附发通道让位（首帧任务与参考媒体
  官方互斥），跨镜一致性只剩分镜图本身与文字角色锚——分镜图已把该镜外观与空间
  画定时划算，角色中途入画或需设定图补细节的镜不适用。详见 `docs/agents/anchor-frame.md`。
- **首尾帧衔接=显式 opt-in、仅 native**：章级 `frame_chain: true`（或 `--chain`）；
  只焊某两镜时在上游镜写 `shots[].frame_chain: true`。**代价要说明**：参与镜退回首帧任务、设定图与板附发让位。
  链邻居=**成片里紧接着出现的那一镜**
  （遇转场断链·弃用跳过·`--approved-only` 不改邻居·下一镜缺任一比例图不成立）；
  衔接镜按「过渡专写」写 `video_prompt`（见节点①）。
- **★焊缝两端铁律（开了衔接才适用）**——焊缝只在**上游真发末帧到下游分镜图**
  且**下游真把它当第 0 帧硬锁**时成立。四种镜归档：

  | 这一镜 | 收得到上游末帧 | 发得出末帧 | 成片里的形态 |
  |---|:--:|:--:|---|
  | 衔接参与镜（章级/镜级 frame_chain） | ✓ | ✓ | 前后焊死，画面自动连贯 |
  | 转场镜两侧 | — | — | 断开，从新画面重新开始（这正是转场的用意） |
  | **写了 previz 末帧**（`last_frame_ref`） | ✓ | ✗ | 上游焊进来，自己收束到 previz 终态、不焊下一镜（那处硬切不补软切） |
  | **参考孤岛 / V2V**（`sketch.reference` / `previz_v2v`） | ✗ | ✗ | **链上孤岛**：独立一镜，再切到下一个 |

  孤岛成因是协议级的：参考任务**没有首/末帧槽**（分镜图只是 `reference_image`）。**衔接章里**引擎在孤岛两侧
  **自动落 `seamless` 无缝转场**（0.1s 柔切、静音、`transition.auto="island"`），
  配置一撤自撤、手写转场不碰；
  缺省章无缝可言，遗留的自动软切会被撤走。**指挥层三条强制要求（衔接章）**——
  孤岛两侧不再手工加转场／不连开一片／**开完先看链态再烧钱**
  （`--dry-run` 或 `transition sync`）——详 kinema-sketchboard「链上孤岛」。
- **分辨率**：默认 config 档位 1080p；`gen-video --resolution 480p|720p|1080p|4k` 临时覆盖，
  **4k 须 `--yes` 二次授权**（见防烧钱铁律）。
- **换视频厂商的边界**：备选 `veo`/`minimax-h3` 已接入（`defaults.providers.video` 一行切换），但
  **dubbed 对口型是 seedance 独有**——veo/minimax-h3 收到配音会显式报错导向 seedance；
  切了备选厂商只能走 native/kenburns（两家输出都恒带原生音频，适合 native）。
- **简写**：`--motion`/`-m` `a`=kenburns · `b`=native · `c`=dubbed（等价 `--kenburns/--native/--dubbed`），写指令更快。
- 引擎按模式自动编排：kenburns=生图→TTS→合成；dubbed=生图→TTS→图生视频(对口型)→合成；native=生图→图生视频(原生音画)→合成。

**配音引擎与凭证**：默认用**豆包语音合成大模型 `seed-tts-2.0`**（provider `seedtts`，标准合成，
`/api/v3/tts/unidirectional/sse`，`X-Api-Resource-Id: seed-tts-2.0`）——uranus 音色是**确定性固定音色**
（番茄/剪映同款），同角色**全程零漂移**，是模版路（显式例外）的配音引擎。
定制路走 seed-audio-1.0（provider `doubao`）：档案音作每句的参考音，声线描述与表演提示进剧本正文。
⚠️ 不要用它的 speaker/纯文本模式逐句配固定角色：音色会漂移；那两种模式只适合音效/氛围/音频作品。
两者共用**独立语音凭证** `ARK_TTS_API_KEY`（不是 ARK_API_KEY！
新版控制台单头 X-Api-Key；console.volcengine.com/speech）。语速：project 顶层 `speech_rate`（-50~100，越大越快）。

**角色音色表**：project 顶层 `voices` 由选角写入（`character add --voice-prompt` 定制立档，或显式
`voice use`），各镜只填 `shots[].speaker` → 引擎自动解析，同一角色全程一致。显式走模版时别名见
`config/voices.yaml`（如 `{"洛":"少年","薇拉":"温柔长辈"}`）。
`voices.yaml` 面向**情景剧/角色扮演**：**★精选 = 角色扮演类音色**（ICL 少年/公子/总裁/御姐/反派/长辈…，
带人设、多情感，专为剧情对白设计，猫箱/豆包同款）；口播音色（Vivi/云舟）降为**旁白/独白**分层；
⚠️有声朗读腔（擎苍/少年梓辛等番茄小说腔）**慎用于日常对话**（会显机械）。也可直接填官方 voice_type。
音色解析优先级：`shots[].voice`（显式）> `voices[speaker]` > 旁白锁 `narrator_voice`（选角写入）> 项目 `audio.voice_id`；解析不到的说话人在真发前被选角闸点名，不回落任何缺省音色。

**⚠ 一镜有几句台词就写几条 `shots[].lines[]`，绝不把多句塞进一个 `narration`。**
两条独立的理由，命中任一条就必须拆：

**① 多说话人 → 音色**。一个镜只有一个 `speaker`，整段 `narration` 恒用**一把声音**念完——
把对白写成 `"narration": "「你到底想干什么？」陆昭没有回答。"` 的结果就是两个人共用一把嗓子，
非常出戏。

**② 多句 → 字幕节奏（同一个说话人也算）**。字幕对单段镜只发**一条**事件、横跨整镜时长：
一句话还没念到，后面几句已经摊在屏幕上了——留言的反转、停顿、"他们会发现你"这种收尾全被剧透。
文本长到要折行时还会被按字数硬切，把收尾引号甩到下一行行首（如：
`…说明我们失败了` / `」「不要继续飞升。」`）。**说一句显示一句**才是对的。
`lint` 的 `subtitle_dump` 维度按警告级守这一条。

正确写法是逐句摊开，每句各自 speaker（同一个说话人就重复填同一个名字）：

```json
{"id": 12, "dur": 8, "image_prompt": "…", "lines": [
  {"speaker": "林深", "text": "你到底想干什么？", "emotion": "angry"},
  {"speaker": "旁白", "text": "他没有回答。"},
  {"speaker": "陆昭", "text": "我只想要真相。", "emotion": "sad"}
]}
```

引擎逐句解析音色（`lines[].voice` > `voices[lines[].speaker]` > 镜级 > 旁白锁）、逐句合成再拼成
该镜音轨；字幕也逐句切换，对话框/气泡的名牌跟着换人。**画面不用拆**——同一个机位里的来回对白
本就该是一个镜头，拆成多镜只会让图数与 Seedance 秒数翻倍。
句没写 `speaker`/`emotion` 就继承镜级，所以「一个人说三句 + 旁白插一句」只需给旁白那句点名。
句间停顿写 `lines[].delivery.pause_before/after`（与镜级同一道闸：**仅 kenburns 生效**，
dubbed/native 恒 0——否则等于按秒向 Seedance 买无声）。
**只有一句话的镜**（单人独白、一句旁白）照旧写 `narration` + `speaker`，不必改成 lines。
**native 下 `lines[]` 与 `narration` 等价可见**——引擎的台词判据统一走 `voicecast.shot_lines`，
两种写法都会编进发给 Seedance 的人声句；未跑 tts 时字幕按**字数比例**切镜窗口
（与提示词里的台词时间轴同一份切分），所以拆句数与 `sketch.beats` 的拍数对齐，
字幕就能落在念白的拍点上。

真实 provider 需要环境变量（详见 `engine/config.example.yaml`）：
`ARK_API_KEY`(Seedream 图 + Seedance 视频，一个 key) · `ARK_TTS_API_KEY`(配音 seed-tts-2.0，火山语音控制台单头 X-Api-Key) 或 `MINIMAX_API_KEY`/`MINIMAX_GROUP_ID` ·
`ELEVENLABS_API_KEY`(BGM，为空自动切本地音乐库)。

> **环境没配好就别硬开工**：`doctor` 报缺 ffmpeg / 缺 PyYAML / 音乐库为空（BGM 会退化成正弦
> 嗡嗡声），或用户是换机、首次使用、问「要不要上 MySQL/OSS」「密钥怎么填」——先走
> **`kinema-setup`** 把六道前置节点配齐并 `run --mock` 彩排通，再回到本流程做片。

## 工作流程（默认逐步确认；只有 `--auto` 才一次跑完）

> **产物一律落在 `project/<项目>/`**，未指定项目默认 `project/demo`。一条视频 = 一个章节，
> 命令统一用 `--chapter <项目>/<章节>`。**每道节点：产物落盘 → 让用户打开大屏看 → 停下等确认。**

### 阶段0 · 建项目
用户没指定就用 `project/demo`（没有则建）。**画风先行**：用户点名画风 → 直接用对应
profile；没点名 → 推荐一档并**一句话二次确认**（立项唯一阻塞点）。`project new
--profile <画风>` 时引擎自动把该画风前缀**快照进 `project.style_prompt`/`style_prompt_en`**
（画风单点真源：分镜图/设定图/封面每次生图统一取此字段拼进提示词，新章节继承；
`project set --style-prompt` 可改=全局换画风）。**同时立项即绑定 skill**：`project new`
自动把画风归属的指挥层 skill 落进 `project.skill`（`shinkai`→`kn-anime`、`cyberpunk`→
`kn-cyberpunk`、`narration`→`kinema`；单一真源为编译后的 Agent catalog）——**这样
之后用户只报项目名/编号，你读 `project.skill` 即知该调哪个 skill，无需再点名画风**（画风
解析链 ⓪）；画风与 skill 不一致的特例（如素材复用解说走 explainer 画风但绑 `kn-showcase`）
显式加 `--skill kn-showcase`。**命名规范**：项目 `--id` 用**简短英文单词**（语义对应主题，如 rebirth/duel/inkwood，

### ★节点① · 文案 + 分镜脚本 → 停下确认
把文案与分镜经 `agent plan apply` 写进章节文档。**文案先过材料清点闸与口播语言
纪律（`references/copywriting.md`——30~60s 至少 3 件具体材料、写给耳朵七条、
钩子用正面写法不用翻案句式）；分镜脚本按专业规范写**（字段全集/中英术语对照/
双语规范/铁律见 `references/storyboard.md`；表演物理化、动作—反应文法、机位权力
与换挡节律见 `references/performance.md`——务必先 Read）：
- **★语态先行（旁白不是必填件·写第一镜之前定）**：先定本片的旁白语态，需要偏离
  缺省时写进章节 json 顶层 `voiceover`（不写则由画风归属 Skill 从 Agent catalog 派生）。
  三档：**lead** 解说驱动（科普/说书/榜单/金句/口播——
  旁白是内容主轴，每镜旁白是常态）｜**sparse** 剧情驱动（**漫剧/短剧/游戏叙事的
  正确语态**：对白与动作是主轴——对白逐句 `lines[]`/`speaker`；动作、战斗、情绪
  展示写**纯画面镜**（`narration` 留空＝合法，引擎自动静音占位、`caption` 可补
  无声字幕）；旁白只留给时间跳跃与一句话背景交代，能用画面讲的连这句
  也省掉——旁白镜占比超 40% `lint` 报 `voiceover_heavy`）｜**none** 氛围驱动
  （纯场景＋音效，零人声叙述）。**镜镜旁白的漫剧是解说腔漫剧**：
  把讲述改成戏，让观众看见而不是听说。剧情画风做说书式内容属合法选择——显式声明
  `voiceover: lead` 即按解说语态判。
- `script`：hook / body / cta（塞具体数字）；`style.seed`（固定整数）——
  sparse 剧情语态下这三段是**剧情节拍梗概**（开场钩子/冲突推进/收束悬念），
  不是逐句口播稿，正文在 shots 的对白与画面里
- `shots[]`（5~10 镜）核心字段：`speaker`(角色名) `framing`(景别) `angle`(角度)
  `camera`(运镜·一镜一主运镜——**a 模式下有真实效力**：写「缓慢推近/拉远揭示/左移/
  对角斜移/微旋/凝视呼吸」会直接驱动对应 Ken Burns 风格，未写则八风格按镜号轮换)
  `lens` `lighting` `transition` `dur` `narration`（字幕即由它逐字生成——音字一致）`caption`（仅无旁白纯画面镜的补位字幕）；
  `characters`（**逐镜必填的纪律**：出场角色白名单，`[]`=明确无人出场——设定图挂载缺省全挂+文字锚取材都看它，
  空镜/群像镜不写会被灌成「人物设定总表」）/ `props`（**本镜出现的道具**：提示词点名命中 `name`/`keywords` 即自动挂设定图，
  措辞不符/重名时显式列出兜底）标注该镜出场者
  （除非用户明确要求英文，分镜结构字段默认写中文；`framing` 中文或代码均可、**引擎不做枚举校验**，「双人中景」这类组合口径照写）
- **叙事元数据（选填·自由文本不设枚举·引擎一行都不读）**：`shot_intent`（本镜叙事意图，
  一句话讲清「这镜为什么存在」）/ `narrative_role`（结构位：钩子·铺垫·转折·高潮·收束·CTA）/
  `hero_moment`（叙事高光镜，布尔；一集 1~2 镜足矣）。**诚实边界**：标 `hero_moment: true`
  **不会让引擎多花钱**——不升分辨率、不加候选宫格、不改运镜，它只供分镜单 lint 与人工审片
  核对节奏。要给某一镜更高成本，唯一正道是显式写 `shots[].profile` 指向更贵的画风档，
  引擎绝不自动升档；与 `priority` 分工：priority 管「缺预算砍谁」、hero_moment 管「重点保谁」
- **分镜单体检（写完必跑·零成本纯计算）**：`python3 -m kinema lint --chapter <项目id>/<章节id>`
  ——**最后一次改动之后还要再跑一次**：交付陈述里的 lint 结论必须出自末次改动后的
  那一次，中途改过任何画面/文案字段就重跑，别拿改动前的「0 警告」收工。
  全维度扫描（新增维度只改引擎，本清单跟着 `variation.py` 走）：**场景连续性**（`scene_unanchored`：正镜没写 `shots[].scenes` 且语料
  点不到注册取景地=场景全靠模型抽、相邻镜极易跳景；`scene_jump`：相邻镜场景直切且
  中间无转场镜，点名复核）/ 相邻镜运镜雷同 / 有台词镜缺 `emotion` 或情绪单调 / 景别分布过平 /
  **提示词里的反 slop 空词**（唯美·氛围感·电影感·高级感…每条直接给「物理化改写」方向）/
  **抽象情绪词**（画面描述写「愤怒/悲伤」这类情绪名词——`emotion_abstract` 逐词给
  身体化改写，纪律见 `performance.md`）/ **画面代词**（画面字段用「他/她/它」——
  `prompt_pronoun`，设定图挂载按 name/keywords 文本命中，代词挂不上图）/
  占位旁白与跨镜重复台词 / **旁白文风**（抬价句式·汇报腔词·名词化·收尾宏大词·
  同连接词开头五项——写法纪律见 `copywriting.md`）/ **视觉换挡间距**（`shift_gap`：
  连续超 30s 无一次可见换挡即点名区间，info 级，节律见 `performance.md`）/
  `hero_moment` 分布 / **`video_prompt` 里的多镜语法**
  （「Shot 1:…Shot 2:…」「镜头一…镜头二…」——一镜一次调用一个视频文件，
  一条提示词排两个镜拆不出第二段素材；预防性纪律，只告警不拦）/
  **`video_prompt` 复述 `image_prompt`**（字符 n-gram 重合率超阈值即告警；只在 dubbed/native
  判——kenburns 不读 `video_prompt`）。`gen-image` 会在生图前自动跑一次同款软闸
  （**只提示不阻断、不落盘**）。阈值可用章节顶层 `art_direction` 旋钮调：
  `{"variety": 1-10, "motion": 1-10, "density": 1-10, "avoid": ["本片忌讳的词"]}`
  ——variety 管重复容忍度（运镜/景别/情绪）、motion 管「多少镜必须写 camera」、
  density 管旁白语速带（字/秒）。**旋钮只改告警，永不改画面**（不换运镜、不改提示词、
  不影响成本）；不写整块就按中位 5 判。空词表单一真源在引擎 `pipeline/variation.py`，
  别在 skill 里另抄一份。
- **★分镜丰富度铁律（Seedance 按秒计费——提示词写满才对得起这笔钱）**（动作链十条铁则/运镜纪律/反模式清单**全文详 `references/video-prompting.md`**，
  强制遵循）：`video_prompt` **绝不许是一句话**，按**五层结构**写满——**250 字以上为佳**
  （引擎地板只有 140 字，那是"拦一句话打发"的下限，不是目标；出过片的成品镜在
  250~450 字这一档，`references/storyboard.md` 的标准示例就是其中一条 351 字的真镜。
  不设硬上限，但字数必须来自五层写全，不是来自复述首帧——复述会被 `prompt_echo` 抓）——
  ① **主体表演层**：动作链 2~3 拍（起势→主动作→收势），带**具体的身体细节**
  （手指怎么动/重心怎么移/视线落在哪），入拍即在动作进行中（首帧静止感是大忌）；
  ② **微表情层**：表情怎么变（如「笑意从眼角先褪，嘴角撑到最后」）——表演的灵魂；
  ③ **次要运动层**：发丝/衣料/道具/环境粒子对动作的响应（马尾滞后半拍甩出/衣摆掀起/
  尘光被带起）——**丰富感主要来自这一层**；
  ④ **光影变化层**：光线在这一镜内怎么走（`light_shift` 结构化位）；
  ⑤ **收束层**：`end_state` 明确终态定格在哪（下一镜的衔接面）；
  ⑥ **声音层**（native 专属，**零额外成本**——同一次调用写与不写同价）：这几秒听见什么，
  按拍写进 `sketch.beats[].sound`（深度档，精确到秒段）或整镜写进 `sfx`。
  **声景也是动作指令**：写「铜铃在撞击时炸响」模型会真把那次撞击演出来，
  写「远处闷雷」它会给天光一次压暗——声音层是唯一能反向驱动画面的一层。
  **三层动作分级纪律**（多人/群像镜防乱动）：主体做主动作链；次要人物只做持续微动
  （呼吸/眨眼/视线流转）与被聚焦回应（点头/嘴角轻扬）；**禁止群演大动作**（起身/横穿）。
  **双轴运镜铁律**：每镜最多两轴运动（推+摇可以，推+摇+升=失控）；特写（大特写~近景）
  绝不配大幅环绕/旋转（崩脸陷阱）。仍恒守增量编译：五层全是「变化」，主体外貌与场景
  一个字不复述（`prompt_echo` 会抓）。
- **★小说改编细节搬运纪律（源头是书时必守）**：拆分镜时**逐段对照原文**，把小说里的
  具体动作、微反应、道具细节、环境响应**按属性归位**搬进分镜——静态细节进 `image_prompt`、
  动态细节进 `video_prompt`/`action`、故事讲述进 `narration`、终态进 `end_state`；
  **禁止把一段有血有肉的戏压缩成一句概括**（「他接住了她」是旁白，不是分镜——原文里
  「右腿一软/踉跄前扑/比看上去轻得多」全是可拍的表演细节）。写完自查：拿原文段落
  与分镜对照，**原文里每个可拍细节都应能在某个字段里找到落点**，找不到的要么补进去、
  要么明确弃（弃了就 `decision add` 留痕）。
- **★场景连续性铁律（跳景=最高频失败）**：① **每镜必填 `shots[].scenes`**
  （取景地白名单，与 `characters` 同为逐镜必填；真没有取景地的空镜写 `[]`）——
  不填=场景全靠模型自由发挥，同一段戏里会抽出「白天街头」；
  ② **同景段共享环境连续性句**：同一段戏的每镜提示词都带同一组「时段+光源+环境词」
  （如「渊口夜景+星涡蓝白光+补光灯粉白」），并显式写「场景光线延续前后镜」；
  ③ **跨景在提示词里写明时间跳跃**（不是加转场——转场只由用户主动插）；
  `lint` 的 `scene_unanchored` 点名漏填取景地，`scene_jump` 只请人复核直切读不读得通。
- **先定导演意图，再挑技法（排第一镜之前做）**：给整条片子写**一句话意图**
  （「我要观众看完觉得＿＿」），跟用户确认后按 storyboard.md 的「导演意图统一」
  选一个**基调档**（静观 / 推进 / 压迫），运镜·景别·剪辑节奏·光位·配乐全部统一服从它。
  **反过来先挑好看的运镜再凑分镜是点名禁止的做法**——每镜都在炫技，观众记不住任何感受。
  确认后 `decision add --chapter <项目>/<章节> --choice "全片意图：…"` 留痕。
- **运镜智能选择（dubbed/native 出片档次的关键）**：逐镜按 storyboard.md 的
  「镜型→运镜智能推荐」表配 `camera`——开场用升镜揭示、情绪反转用希区柯克变焦、
  主角登场用**迈克尔·贝英雄环绕**、顿悟反应用斯皮尔伯格惊愕推近、对白双主体用
  焦点转移、长镜内转场用前景擦镜……**一集 8~12 镜配 2~4 个▲进阶档**做记忆点，
  其余走●稳定档；■高危档（甩镜/急推/子弹时间/韦斯甩摇）用户点名才排，且在
  `gen-video --dry-run` 里向用户点出这镜是高危运镜。措辞直接抄预设库
  **共 21 条**（经典技法 12 + 大师签名 9）的双语列，不要自创快系运镜词。
  **2D 手绘画风例外**：手绘动画没有摄影机也没有物理，依赖真实光学的几条
  （希区柯克变焦/卢贝兹基漂浮/FPV/子弹时间）别用，改走 `kn-anime` SKILL 的
  《2D 作画运动语法》（一拍二顿挫 / 止め絵 / 速度线 / 残像）；`lens` 字段一并留空。
- **跨镜连贯性自检（分镜写完、生图之前，逐对相邻正镜过一遍）**：按 storyboard.md
  「跨镜连贯性自检」查五条——视线方向 / 不跳轴（180° 线）/ 景别阶梯（跨一档最稳）/
  光位与色温延续 / 主体出入画方向。这一条查的是**不断开处怎么接得住**，是你该主动做的；
  **要不要断开（插转场）是用户的取舍，你不代做也不主动提议**——判完发现"怎么接都跳"，
  如实说明位置与原因即可，别顺手插一个转场把它盖过去。发现问题**当场改分镜**，
  别留到出图后再 retake（那时钱已经烧了）。
- **提示词双语（中文为主，英文为辅）——硬要求，`lint` 的 `prompt_bilingual` 维度按
  警告级守卫**：写了中文就必须有英文对位，缺了它路由到 `prompt_lang=en` 的模型
  （nano-banana / veo）会静默回落中文，不报错不留痕。
  - `image_prompt`(中文·真源) + `image_prompt_en`(英文·语义对译，供海外模型自动选用)
  - `video_prompt` + `video_prompt_en` **只写增量**（运动/运镜/光线变化）；`negative_prompt` 写负面约束
  - ⚠️ 中文提示词**只写这一镜不同的动作/姿态/表情/机位**，不重复外貌与场景
    （设定图+引擎已前置）；英文版用地道电影术语（rim light/dolly in/shallow DOF）
  - **增量编译铁律（video_prompt·续拍句式）**：视频请求**恒带这一镜的分镜图**
    （native/首尾帧=首帧驱动，dubbed=参考图），画面基底已经给定——引擎自动前置增量契约句，
    你只写「在此基础上变了什么」。**复述主体外貌与场景=要求模型重画一遍=跨镜漂移头号来源**
    （`lint` 的「复述重合率」维度量化告警）。句式骨架：
    **动作怎么变 → 终态停在哪 → 光线怎么走 → 镜头怎么动**，如「陆昭从伏案的姿势缓缓直起上身，
    手停在半空，窗外天光由暖黄渐转冷蓝，镜头缓慢推近」（画面字段用注册名点名，
    不写「他/她/它」——storyboard.md 铁律 8）。
    - **缺笔不回退 `image_prompt`**：没写 `video_prompt` 时引擎按
      `action`(动作) / `end_state`(终态) / `light_shift`(光线变化) 三个结构化位拼 delta 骨架
      （**两语种都发**——这三个位没有 `_en` 对位，英文模型下只换标签 `Action:` / `Ends on:` /
      `Light shift:` 发同一批值），六者全空才落固定兜底句（"保持不变 + 轻微自然运动"）——
      不漂移但那镜没有运动设计，`gen-video` 会逐镜点名（只点真空着的镜），看到就补
    - **★运动规划两档（缺省深度档）**：视频模型消化长动作靠的是**分段时间结构**——
      「第几秒干嘛」它照着演，一整段散文则要它自己猜先后与配速，出片常见症状就是把三件事
      压成一件、或前半段空转。两档的差别只在**过程写在哪里**，不在写多写少：

      | 档 | 怎么写 | 引擎怎么发 | 何时用 |
      |---|---|---|---|
      | **深度档（缺省）** | `guide: "sketch"` + `shots[].sketch.beats[]` 逐拍 | 编译成分段时间轴前置进请求：seedance-2.5（`timeline_unit: second`）发「第0-3秒：…」秒段，seedance-2.0 系列含 mini（`timeline_unit: shot`）不响应秒段、发「第1段：…」顺序段头，`t` 仍决定拍序与板 | **默认全用**——但凡这一镜有先后次序 |
      | 普通档 | 只写一段式 `video_prompt` | 原样发出，无时间结构 | 例外：纯氛围空镜、单一姿态的静镜 |

      **每拍五个位**（`beats[]` 的条目）：`t` 秒段（`"0-3s"`）· `action` 这几秒发生什么
      **（含该秒段的环境动态：雨、蒸汽、人群、水花——"场景描述"落这里）** · `camera` 机位
      怎么动 · `light` 光线怎么变 · `sound` 这几秒听见什么。
      **`sound` 在 native 下随时间轴一起发给模型**（编成「声：…」，与板上的「声」同一个字段）
      ——native 是模型原生出音、写与不写同价，逐拍音效脚本是这条路上最便宜的质感增量；
      dubbed/kenburns 下不发（声音归合成段，发了没有消费者）。写了逐拍 `sound` 的镜，
      镜级 `sfx` 会自动让位、不再重复发一遍。`framing` 一个位仍只喂简笔板、不进提示词。
      **拍数按 2~3 秒一拍切**（5s punch 镜 2 拍、8~12s 主戏镜 3~5 拍、12~15s 揭示/
      长镜 4~6 拍——主戏镜缺省 8~12s，见 video-prompting.md 第七节），过密模型会自行丢拍。
      这是**你手写 beats 时的配拍口径**，与引擎代切时的收敛上限不是一回事：
      `sketch gen` 没有 beats 时会按 `TARGET_BEAT_SEC`（1.2s/拍）自动拆，那是「画板时
      每格别塞太多」的上限（硬底线 `MIN_BEAT_SEC` 0.8s/拍），**不是手写目标**——
      按 1.2s/拍手写会让 Seedance 丢拍（abyss 镜1 的 9 拍铺 5s，四拍整段未执行）。
      两个数分别是「你写多粗」与「引擎代切多细」，别互相套用；本仓写得最好的两章
      authored beats 正是 2~3.5s/拍。
      **打斗/追逐等动作戏另有整套工法**（力量关系曲线、因人设招、停—爆—停配拍、
      构成式拆镜与受击反应）——写前必读 `references/action-direction.md`。

      **★描述厚度是硬底线（两档同等适用·`lint` 的 `prompt_thin` 维度按警告级守）**：
      **绝对禁止一句话打发**。「全程对称构图不破」「环绕不超过半圈，主体居中」这种
      **只有约束没有内容**的写法一律不合格——它没告诉模型任何可执行的东西，模型只能
      退回训练集均值，这一镜就白花钱了。每一镜的 `video_prompt` 必须写满下面五项里
      **至少四项**（这是"专业地描述一个镜头"的最低配，不是上限）：

      | # | 必写项 | 反例 → 正例 |
      |---|---|---|
      | 1 | **动作的力学**：发力顺序、重心怎么走、速度曲线（先沉后爆/匀速/收势） | 「冲过去」→「重心先后沉再猛推向前，最后半步收势卸力」 |
      | 2 | **物理反馈**：受力处怎么响应——火星/水花/碎屑/形变/电弧的方向与量级 | 「打中了」→「接触点炸开扇形白色火星并沿义肢向下泄流」 |
      | 3 | **次级动画**：头发/衣摆/绳索/液面的**滞后与惯性**（几乎所有"AI 感"都出在这里没写）；成品措辞按驱动动作查 `references/secondary-motion.md` | 「转身」→「高马尾滞后半拍甩出，风衣下摆炸开两片」 |
      | 4 | **镜头的执行**：不只报运镜名，写清速度、跟随关系、何时收速 | 「跟拍」→「在侧面与主体等速跟随，刃光越过胸甲时略微收速」 |
      | 5 | **材质与光的响应**：金属/布料/湿面在这段运动里怎么反光、怎么起褶 | 「手握刀」→「手套布料随握力起褶，铬合金上电弧爬两圈」 |
      | 6 | **声音设计**（native 必写，其余模式可略）：这几秒听见什么，逐拍写进 `beats[].sound`、整镜写进 `sfx`。**写可数的声音事件，不写声音的底子** | 「打斗声」→「刃入甲的脆响，紧接金属磕击叠电弧爆鸣，断棍落地弹两下」 |

      写完自检一句：**把这段话给一个没看过分镜图的动画师，他能不能画出来？**
      （第 6 项另加两句：**动作改了，`sfx`/`beats[].sound` 必须同改**——声景与动作
      对不上时模型会去演声音说的那件事。**「底噪 / 垫底 / 持续的嗡鸣 / 声床 / 白噪」
      这类词不要写**：模型会照办，交回一片没有事件的稳态宽带噪声——一个雨夜
      室内镜，写「嘀嗒叠成密集底噪、低频嗡鸣垫底」拿回的音轨包络变异系数只有 0.35、
      频谱在 20Hz~5kHz 平铺，耳朵读作嘶声；同章另一镜写「最后一秒一声更清脆的
      单独嘀嗒」，模型照做且末秒能量明显突出。氛围要用可数事件堆出来：
      「每两秒一次的挂钟嘀嗒」「一次车轮碾水声」，而不是「持续的环境底噪」。
      **闭声镜尤其要紧**——那一镜只有环境声，噪声无处可藏。）
      画不出来就是还没写够。

      **深度档的三条配套纪律**（消重，**不是删描述**——砍到只剩约束是最严重的违规）：
      ① `beats` 写**执行时序**（第几秒干嘛），`video_prompt` 写**整体运动设计**
      （上表五项）+ 贯穿全镜的硬约束。两者是不同层，不是同一批话说两遍：
      秒段清单不许在正文里复述一遍，但正文该有的厚度一分不能少；
      ② **终态只写在 `end_state`**，正文不再复述（引擎两处都会发）；
      ③ 逐拍写了 `light` 就**清空 `light_shift`**（同一条光线弧线不写两遍）。

      **常规档同样受厚度底线约束**——它没有 beats 兜底，正文是模型拿到的**全部**
      运动信息，写薄了后果只会更重。常规档只在两种情形用：用户点名要，或这一镜
      根本不调用视频模型（kenburns）。

      **`t` 写不写**：写死=拿到有意的非均匀配速（3/4/3），代价是改 `dur` 后不会自动重算；
      留空=引擎按实际请求秒数均分。写了 `t` 就归 `lint` 的 `beats_span` 维度盯着，
      改过时长而秒段没跟着改会被报出来。
    - **首尾帧衔接的镜（`frame_chain` 显式开启才有）改写"过渡专写"**：引擎实发末帧时会追加
      「只写首帧到末帧之间的过渡过程、不复述末帧、运动自然收束在末帧上」铁律句，
      你把 `video_prompt` 写成过渡句式、`end_state` 写成下一镜首帧的姿态即可；
      末帧长什么样不用写（模型看得到那张图）。`--dry-run` 里带 `末帧=镜N` 标记的就是这类镜
      （跨转场断链·弃用镜跳过·下一镜缺图则整镜退回常规生成，标记与实际请求恒同源）
- **反主观词铁律（写提示词第一纪律·不是审完再改）**：提示词里**只写镜头拍得到的物理事实**
  ——光线走向、材质工艺、构图占比、身体姿态、空气介质；**主观评价词一律先翻译成视觉成因**
  再落笔（「唯美」→「逆光暖调，发丝边缘透光，背景高光散成圆形光斑」；「氛围感」→「雾气与浮尘
  在斜射光束里翻涌」；「高质量/高清/大师级」→ **直接删**，画质是画风前缀与 `--resolution` 的事，
  写进提示词只挤占有效 token）。模型渲染不出评价，只会退回训练集均值那张"AI 感"的图。
  **空词表与逐条改写建议的单一真源 = 引擎 `engine/kinema/pipeline/variation.py` 的 `SLOP_TERMS`**
  （`lint` 命中即逐条报出改写方向）——**skill 侧只讲纪律、绝不复制词表**，免两处分叉；
  要新增/修订空词，改 `variation.py` 一处即全链生效（详见 references/storyboard.md「铁律」6）。
- **字幕语言（建项目时就定）**：`project new --subtitle-lang zh|en|both`（缺省 zh，
  新建章节继承）。项目是 **en/both 时写分镜必须成对产出 `narration_en`**（信达雅
  对译，不是机翻腔；TTS 仍读中文 narration，英文只进字幕）——both 出中文主行 +
  英文副行的标准双语版式，出海双投/外语学习内容用它。用户没提字幕语言时默认 zh，
  但**出海/双语/英文关键词出现时主动问一句**。
- **打印专业分镜表给用户**（镜号/景别/角度/运镜/时长/台词/双语提示词），
  `kinema studio` 可开大屏逐镜核对。**停下等确认**。

### 节点①.7 · 3D 导演编排（**可选**，有戏可排时才用）

**什么时候用**：这一集有明确的**调度**——谁从哪走到哪、几号机位、镜头怎么动。
纯氛围/口播/信息类（无走位可言）**直接跳过**，它是增强不是必经节点。

**怎么用**：让用户在 Studio 打开 `#/stage/<项目id>/<章节id>`（章节页主列「3D 导演台」区块的「◈ 进入导演台」按钮），
在浏览器里摆灰模角色、指派动作、画走位路线、设机位、选运镜 preset，逐镜「渲染 previz」。
产物自动落回本集 `shots[]`：首帧（→ 分镜图，该镜无图时才登记）· 末帧（`last_frame_ref`，
发 Seedance 末帧时优先于衔接链）· 参考片（`previz`）· 运镜措辞（`camera`）。

> **接缝提醒（见「焊缝两端铁律」）**：登记了 previz 末帧的镜**不再焊下一镜**（末帧槽被
> 自己的终态位姿占用）——那一处是硬切，`--dry-run` 会标 `末帧=previz`；**引擎不替你
> 补软切**（previz 常整段连着登记，自动补等于给整章塞一串转场），要软化自己插一个。
> 但真开了 `--previz`（V2V）之后它就成了**链上孤岛**——参考视频分支下分镜图只是
> `reference_image`，首/末帧槽都不存在，两侧接缝由引擎自动落无缝转场，别再手工加。

**你在这一步该做什么**：
- **用户没开口就不要替他排戏**——控制台是导演的工作台。**但用户把编排交给你时
  （粘来「🧠 复制 AI 编排指令」的指令，或直接说"帮我照分镜图编排"）就是你的活**：
  逐镜 **Read 分镜图 `shots[].image`** 与 narration/action/camera/framing，把章节文档
  顶层 `previz` 场景快照重写为与分镜构图对位的编排（角色站位/朝向/走位/动作轨/
  机位构图）——引擎**不做任何自动编排**（首次进入是空台+每镜一个机位的结构骨架），
  代排只有这一条路（照分镜图对位需要视觉理解，智能归指挥层）。
  格式=控制台 serialize（指令里带全套合法 key 与 schema）；纪律：只写 `previz` 块、
  cuts 时长 4~15 整秒且首尾相接、camera preset 只用目录 key、对话镜用
  `cameras[].frame` 三分构图（±0.167，视线侧留白）、走位起点必须=站位、角色 y 恒 0；
  特殊调度可给机位写 `cameras[].path`（自定义轨道·世界坐标 ≥2 点：位置沿它弧长
  匀速走完本镜且结束帧必达终点，yaw/dist 随之失效）——常规镜别用，preset 程序轨道足够。
  写完让用户刷新导演台查看（同一条 restore 路径）。
- 用户排完后，`camera` 字段已由 preset 写好，**别再手写覆盖**（会与 3D 里的运动分叉）。
- 想让成片跟随预演的运动：`gen-video -m b --previz`（**opt-in 花钱开关**——按 token 计费
  且输入视频秒同样入账，5s previz ≈ 每镜多花 5 秒的钱，务必先 `--dry-run` 给用户看报价）。
  **它还会改变整章的接缝结构**：开着 V2V 的镜全部变成孤岛，两侧自动补软切——
  `--dry-run` 的输出里逐条打印，先看一遍再决定要不要真跑。
- 只有手上已有一段现成预演 mp4 时才用 CLI：`previz register --chapter x/ch --shot N
  --file 预演.mp4 --camera <preset_key>`（运镜全表 `previz presets`）。

**36 个运镜 preset 与 `references/storyboard.md` 的《进阶运镜预设库》是同一套措辞**
（21 条逐字节复用）——手写 `camera` 与 3D 选 preset 给模型的是同一句话，两条路径不分叉。

### 节点①.8 · 简笔分镜预演板（**可选**，与 ①.7 逐镜互斥）

3D 排戏之外的第二条运动预演路径：把一镜按时长拆拍（beats，拍数由引擎按 dur 收敛）→ 引擎生成一张
「铅笔素描 + 五色标注箭头」的分镜预演板（0.3 元/板·网格按拍数恰好填满）→ gen-video 时
beats 编译成**分段时间轴**控制逐拍先后（响应秒时间戳的型号才拿到精确秒段）；缺省档（dubbed 的参考媒体
模式与 native 的全能参考）板在盘即附发；衔接章里板不附，要让某镜走参考孤岛才显式
`sketch ref --shots N --state on`（开一镜断一条接缝，只给真需要的镜开）。适合动作节奏
要逐秒钉死、但没有走位调度可排的镜（3D 台强在空间调度，简笔板强在时间节奏）。
**同一镜二选一**（`shots[].guide` 仲裁，缺省 previz 优先）；协议、拆拍工法与质检
四查全在 **`kinema-sketchboard` skill**（命令族 `sketch`，Studio 章节页
「SK 简笔分镜台」区块）。

### ★节点①.5 · 设定单 + 设定图（一致性根基）→ 停下确认
> **长文本链路（上传小说改编 / `kinema-novel` 原创）走铁律9「文字先行·图片留空」**：
> 本节**只做设定单的文字部分**（`character/prop/scene add` + 逐字段补全），`project refs`
> 整条留到用户下令那一刻；全书文字做完后出《出图就绪表》再停下。单条视频不受此限，照常逐门走。

**从定稿文案/分镜里自动分析出「设定单」**：需要哪些**角色**（外貌/服装/发型/持武器）、**道具/武器**、**场景**——
这样就有了完整脚本 + 完整角色/物品/场景设定。写进项目：
```bash
python3 -m kinema project set  <项目> --scene "从脚本提炼的固定场景一句话"
python3 -m kinema character add <项目> --name 师父 --voice-prompt "五十岁男性，温润中音，语速慢" --appearance "白发苍劲老者" --outfit "深褐道袍" --hair "白发束发" --weapon "拂尘"
python3 -m kinema prop      add <项目> --name 系统面板 --desc "半透明发光游戏UI面板"
```
> **★角色缺省有精神**：`appearance` / `role` / `outfit` / `hair` 不写黑眼圈、眼袋、血丝、憔悴、无精打采这类疲态，
> 夜班/凌晨题材也不推导出来——只有用户明确要求角色疲惫时才写，并把该特征登记进 `visual_requirements`
> （lint `character_fatigue_look` 与 `project refs` 出图闸据此放行，未登记的角色不出设定图）。
>
> **★角色清单前置（写设定单时顺手填，一致性投入产出比最高）**：`character add` 之后用 `character set` 补齐人设字段，
> 给主要角色补五个字段（都是**系列级常量**，一次想清楚全系列，**绝不按集填**——设定集是系列→章节单向覆盖，
> 按集填的下次 `project refs` 就被冲掉）：
> `required_emotions`（这个角色全片要演到的情绪，如 `["平静","愤怒","含泪"]`）/ `required_actions`（关键动作）
> / `required_views`（三区两视外还要出现的视角，如俯视）——写分镜时据此对表，别让某个角色从头到尾一个表情；
> `silhouette_notes`（**剪影辨识度要点**，如「左肩甲高耸、右袖空荡、发尾一撮翘起」）——**会拼进角色设定图提示词**，
> 跨镜一致性的强锚点，优先填；
> `constraints`（硬约束/禁忌，如「绝不摘面具」）——**刻意不进设定图提示词**（会与「全身空手」
> 这条引擎铁律打架），你要做的是写分镜时把它编译进该镜 `shots[].negative_prompt`，并在验收角色一致性时拿它当判据。
> ⚠️ **改了 `silhouette_notes` 存量设定图不会自动重生**（同一角色已有 sheet 时 `project refs` 直接跳过）
> ——须 `project refs <项目> --only character:<名> --force` 单张重生（**花钱、先向用户要授权**；旧图自动进版本栈可回滚）
> 。别把「填了字段但图没变」当成功能没生效。

**打印设定单给用户确认** → 通过后生成设定图：
```bash
python3 -m kinema project refs <项目> --concurrency 8   # 角色/场景/道具设定图 → assets/refs/
#   ↑ 并发 8 张同时出（缺省 4）。十几张设定图串行要等很久，这是最直接的提速；
#     某张失败不拖垮整批，重跑会自动跳过已成功的。
```
> 角色设定图恒按**【三区两视铁律】**出：横向三区宽度比约 40%:30%:30%——左区＝锁骨以上正面肖像大特写，
中区/右区＝正面与背面全身立像（同地平线等高等比），背面必出；**全身像无条件空手、不持握不佩挂任何
武器道具**——角色有 `--weapon` 时武器不上角色表，走独立的道具/武器设定图（保持全身像为干净的角色参考底图）
。引擎已内置，你只需把武器填进 `character add --weapon`。**道具设定图独立出**（`prop add`）
，只在提示词点名命中它的分镜里挂——不会无差别塞进每个角色的设定图（避免「猫勇者手里被塞进水杯魔王」
类事故）。`--keyword` 只写专名与别称（「绿皮书」「银杏叶」），不写「书」「杯」这类单字品类词：
命中是文本匹配，「书」会命中「书架」「书脊」，把道具图挂进道具不该出现的镜、与该镜的负向约束打架；
`shots[].props` 显式表只补挂不排除，改关键词是唯一修法（`prop set --keyword … --sync`）。**场景设定图另有一档**（`scene add`）：走环境 key art 版式（广角建立镜头／无人物／前中远三层景物、
比例跟随项目），命中方式与道具同源；**把场景登记成道具会套上结构三视物件版式**，「孢子宫殿」
被画成蘑菇战锤。**场景恒是一整幅画面**——不附版式样板、不出多视图并列、不出局部细节框（道具正相反，
靠三视与细节框锁形制）：场景图会被整张挂进分镜当光线与陈设基准，画面里多出来的小图会连同场景一起被当成画面内容参考；
措辞带「设定图 / concept sheet」时模型会在底部补一条材质特写缩略图带。
**场景 desc 必须钉死时段与主光**（如「正午强光、顶光直射」）：不写的话基准图生成时
自选一个时段画进去，之后全链路把它当光线基准——写实档人脸降级路线上它直接顶
`@图片1`，一张自选成黄昏的基准图会把白天戏整镜拖成暮色（lint `scene_daypart_missing`
点名没表态的；已出的图改完 desc 用 `project refs --only scene:<名> --force` 重生）。
**★场景俯视图（与场景基准图恒配对出，没有关闭开关）**：一个场景两张图——基准图交代
「看上去什么样」（透视画面、光线与陈设基调），**俯视图**交代「空间怎么摆」（掀顶后的
墙体与出入口、门窗与高差、陈设的正上方轮廓与朝向、可通行地面）。**图纸只画空间本身**：
机位、视野锥、动作轴线、人物站位与走位路线一概不画——那些是「这一场戏」的属性，而取景地
跨场次复用，画死在场景级图纸上会让别的场次照着一套错的调度排机位。
裸 `project refs <项目>` 就会成对出；存量项目重跑只补缺的图纸，不重付基准图的钱。
只有基准图、没有图纸的场景由 lint 的 `topview_missing` 点名。
两件事必须知道：① 俯视图**以该场景的基准图为参考**生成（故排在它之后，第二波才发请求），
基准图还没落盘的场景**本轮不画**（候选待定稿也算），定稿后重跑 `project refs` 会补出——
盲画那张会占住 `topview_sheet`，此后跳过判据只看文件在不在，这一对图再没机会对齐；
② 它**只随视频请求发出**，且**每镜至多一张**——取该镜的主场景那张（显式 `shots[].scenes`
写在最前那个 > 命中项里系列 `scenes[]` 声明最靠前那个 > 全局固定场景），紧跟它自己的基准图；
主场景没图纸就一张不发。要指定发哪张，写显式 `shots[].scenes` 并把它排第一——只靠镜内文字
先后不生效。
附图配额是硬的（seedance 全图 ≤9、引擎侧钳 7），逐个场景各挂一张会把作者点名的道具挤出去。
提示词里逐张点名职责、并声明「本镜仍按自己的机位拍、绝不改成俯视」。
**分镜图侧不挂**——图侧 8 张参考位留给身份与外观。
重出用 `--only topview[:名] --force`（只重画图纸）或 `--only scene[:名] --force`（两张一起）；
局部改造 `refine --id <项目> --asset topview:名 --note "…"` 同源支持。
**画风跟项目走**：俯视图与场景基准图是同一套视觉语言下的两张图，并排要看得出是一家——
引擎会在画风前缀后自动补一句「画风只管线条质感与配色语言、不管观察方式」，把画风里的渲染词
（PBR / 三点布光 / 浅景深）挡在投影方式之外。**但不吃风格垫图**（moodboard 锁的是成片画风，
喂进来会把图纸拉回画面）——要换成手上现成的平面图，走网页灯箱「⇪ 素材直供」。

**★写实人物档（identity_sheet）**：`config/models.yaml` 里 `image.identity_sheet: true` 的
profile（现为 photoreal3d / virtual_production / cg_noir / anime_ldr / cyberpunk 五档），
角色设定图（身份图）走**纯文生图**——不垫版式蓝图、不垫 moodboard，产物因此落在视频侧
的受信豁免内（`sheet_origin=t2i`）。连带两条：① `refine` 局改身份图会被拒绝（局改是
图生图，改完即失去受信）——要改身份走 `project refs <项目> --only character:<名> --force`
重出；② 生视频按镜走 A/B/C 三级路线：A=分镜图照常发（近景正脸随便画——人脸拒发生在
建任务 HTTP 400、不计费），被拒自动降级 B=主场景基准图顶 `image` 位 + 简笔板 + 受信身份图，
板不可用落 C（构图交提示词与俯视图兜底）。作者预判某镜必是近景正脸时，写镜级可选字段
`face_visibility: closeup` 直接从 B 起步（缺板会自动就地生板、计入图像台账；
审阅锁在场的镜不代买板，按无板形态比对审阅稿）。
**人脸拒的处置铁律：降级由引擎自动完成，Agent 绝不为绕闸改写分镜**——把有脸构图改成
无脸/背影/局部是删掉正面表演，不是修复（人脸拒不针对构图，路线 B 带脸照常出片）；
路线 B 出片与设计有出入时，先查场景基准图（它顶 `@图片1`，时段/光线没钉死就修它重出）
与降级日志，不动 `image_prompt` 的表演设计。判据与链路详见
`docs/agents/photoreal-face.md`。

**扩展设定图（opt-in·按需追加）**：`project refs <项目> --expressions --poses`
追加生成两类表演参考——**表情表**（4×3 十二格，`required_emotions` 优先入格、
默认集补满，强度差与易混对判据引擎已内置）、**动作表**（5×3 十五格，`required_actions`
优先入格；角色有武器时对抗类动作持械，与主设定图「全身空手」不冲突——那是身份底图、
这是表演参考）。两张恒直出单张、**不进每镜自动挂载**（设定图 8 张上限，挤掉主设定图
得不偿失）——用法两条：dubbed/native 的关键情绪/动作镜把它写进 `shots[].refs` 显式挂参考；
审片时对照表情与动作是否走样。单张重生 `--only expression:名|pose:名 --force`
（旧版自动入版本栈）；局部改造 `refine --id <项目> --asset expression:名 --note "…"` 同源支持。
**拿不准画风时用候选宫格**：`project refs <项目> --candidates 3` 每项设定图出 3 张候选 →
Studio 项目页宫格点选定稿（或 `project pick-ref <项目> --asset character:名|scene|prop:名 --use N`）——
点选即定稿落位并触发血缘，旧稿自动备份、随时可换选。
提示用户**开大屏看设定图**逐个确认；不满意的改描述后 `project refs <项目> --force` 重生，
或灯箱「局部改造」只改不满意的那一处。**停下等确认**。
> 用户明说"跳过设定集" → `project set <项目> --skip-design`，直接进节点②（以首镜图作固定参考）。

> **★参考库 / 风格垫图（用户给「参考这个风格」的图时）**：用户上传/指定风格参考图 → `project moodboard <项目> --add <图路径>`（或网页项目页「参考库」
上传）。**一旦入库即默认注入后续一切生成**——设定图 `project refs`、分镜图 `gen-image`、局部改造 `refine`、
封面 `cover` 全自动把默认启用的垫图转 base64 喂模型（无需 OSS），整体统一模块画风。**关闭只有三条路**：
① 用户说「这次不要垫图」→ 命令加 `--no-moodboard`；② 某张不想默认套用 → `project moodboard <项目> --off <图>`（留库不删）
；③ 只想某一镜换参考 → 写该镜 `shots[].refs`（`[路径…]` 精确 / `[]` 本镜只靠提示词）或网页分镜卡「⛭ 垫图」
勾选。**别手写整条 moodboard 数组**，用 `project moodboard` 子命令。垫图与设定图共享每镜 8 张参考上限（超出告警不静默截断）
。

### ★节点② · 生图（先首镜确认，再续跑）→ 停下确认
> **长文本链路（铁律9）**：分镜写完只是文字交付，**`gen-image` 不在这一步跑**——
> 等用户看过《出图就绪表》并明确下令出图，且**设定图那一批先出完并通过**之后再进本节。

**先只出两张**确认风格与一致性（省钱、防跑偏）——首镜 + 一个**结构上最不像首镜**的镜
（最好是没有人、没有地面的纯空镜）。只验首镜一张是**不够**的：首镜常与画风前缀里的
隐性构图令恰好一致，那张图完美而前缀的病一点不露，续跑完整章才发现（见铁律2⓪）：
```bash
python3 -m kinema gen-image --chapter <项目>/<章节> --only 1,3 [--mock]
```
有设定集时每镜**强制参考**设定图（场景+出场角色+道具）→ 角色/场景统一。开大屏看首图，OK 再续跑其余：
```bash
python3 -m kinema gen-image --chapter <项目>/<章节>          # 其余镜（首镜已存在自动跳过）
```
某镜不对 → 改其 `image_prompt` 后 `gen-image --chapter ... --only <镜号> --force`。**停下等确认**。

**宫格候选（拿不准构图时，直出可用率 +80%）**：每镜一次出 N 张候选，人点选定稿：
```bash
python3 -m kinema gen-image --chapter <项目>/<章节> --candidates 4      # 每镜 4 张候选（不占画布）
python3 -m kinema pick      --chapter <项目>/<章节> --shot 2 --use 3    # 点选定稿（=通过锁定）
```
Studio 章节页/待审队列有**宫格点选**（点一下即定稿，原版自动归档可反悔换选）。

### ★节点②.5 · 角色跨镜一致性校验（引擎产料 + **你**判定）→ 出图后必做一遍
**这道校验的判定人是你，不是引擎**——引擎只把料备好（零成本纯本地）：
```bash
python3 -m kinema consistency scan --chapter <项目>/<章节>       # 产料：代表帧 + 角色设定图配对清单
```
产物落 `<章节>_work/consistency/`：每镜 `shot_<id>.png` 代表帧（kenburns 就是分镜图缩放拷贝；
dubbed/native 从片段中点抽帧）+ `manifest.json`（帧 ↔ **该镜出场角色的设定图**，绝对路径）。
**接着你自己动手**：按 manifest 逐镜 `Read` 代表帧与对应角色设定图，比**五官轮廓、发型发色、
瞳色、服装款式与配色、体型、标志性配件**是不是同一个人（`characters[].silhouette_notes`/
`constraints` 就是这里的判据）。判完回填：
```bash
python3 -m kinema consistency set --chapter <项目>/<章节> --shot 3 --verdict ok
python3 -m kinema consistency set --chapter <项目>/<章节> --shot 5 --verdict drift \
        --score 0.4 --note "发色由黑变棕、缺了左肩甲" --retake      # --retake=顺手打回重做
```
- **引擎绝不自动打分**：ffmpeg 没有人脸检测，`ssim/psnr` 对「同角色换姿态」无判别力，
  CLIP 拿整帧比灰底设定表量的是版式——所以 `--score` 是**你的主观分**，不填也行。
- **scan 打出「本镜无可比对角色」的镜不是绿灯**：原因有五种（`consistency.REASONS` 单一真源，
  scan 会逐行喊出具体是哪一种）——① 项目 `skip_design`（不走设定集）；② 该镜写了
  `shots[].characters: []`（你声明本镜没角色）；③ 项目还没登记任何角色；
  ④ **`shots[].characters` 点名的角色不在项目角色表里（名字写错）**；⑤ 设定图还没生成
  （先 `project refs`）。①② 是合规跳过；③⑤ 要补做；**④ 最该立刻修**——名字对不上时
  `lineage.required_refs` 按名过滤直接落空，等于这一镜**根本没喂角色设定图**，
  漂移风险最高却最容易被当成"没角色可比"放过。一律别当成"比对通过"。
- `--retake` 的纪律：未锁定镜置 retake（下次 `gen-image`/`gen-video` 自动重生 + 旧版归档），
  **已 done 锁定的镜只留判定当标记、不代人解锁**（要重做先 `review set --state retake`）。
  dubbed/native 判 clip 漂移会**连 image 一并打回**——图生视频恒以分镜图作首帧，根因在图。
- **判定只对被判的那一版画面成立**：重生成/素材直供/局部改造/宫格换选/版本回滚一换画面，
  引擎当场把这条判定整条清掉（CLI 打印「旧一致性判定已作废」）——所以重生后要**再 scan 一次
  重判**，别指望旧判定跟着新图走，也不会看到新图上残留上一版的「⚠ 角色漂移」角标。
- 动态化之后（节点⑤）再跑一次 scan，这次比的是片段中点帧；判 drift 时的 note 会编译进重做意见。

### ★节点②.7 · 封面（生图过审后必做，别拖到成片）

> **这一节是本流程被跳过次数最多的一节**（新项目建好、图也出了，
> `#/projects` 主卡与项目页章节区却是整片空白）。原因是它不影响成片、不报错、
> 不挡下一步——**唯一的症状只在网页上**，而做片的人此刻正盯着终端。
> 所以两条硬规矩：**① 系列封面在「项目建好 + 设定图过审」后立刻出，不等分镜图；
> ② 每建一个新章节，出完该章分镜图就补这一章的章节封面。**
> 引擎有三处点名，看到任一条就当场执行，不要留到"最后一起做"：
> `gen-image` 收尾的 `_warn_cover_missing`（逐条打印该跑的命令，正常收尾与「图已全出」
> 重跑两条出口都发）· lint 维度 `cover_missing`（正镜图齐而章节 `cover` 仍空即报，
> 每轮生图的软闸也会带出来）· Studio 的 `NO COVER` 角标与项目页主视觉占位。
```bash
python3 -m kinema cover <项目>                          # 系列主视觉（首次·竖3:4+横4:3双套）
python3 -m kinema cover <项目> --chapter <章节> --desc "本章画面描述（指挥层精写）"
```
- **为什么是必做且在这里做**：Studio 项目卡与章节卡的图源是「封面 → 成片海报帧 → 分镜图」
  三级回落，**封面是唯一为这个位置设计过的图源**——不生成，卡片就只剩分镜图兜底（角标标
  `NO COVER`），项目页主视觉位是占位块。封面只依赖设定图与画风（引擎自动把角色设定图/
  系列封面背景/垫图喂作参考），生图过审后即可出，不必等合成。
- **顺序铁律**：先系列后章节——章节封面以**系列封面背景**为首张参考图 + 同画风前缀同 seed，
  三锚点锁系列感；系列封面只在首次或改版时生成（已存在自动跳过，重生加 `--force`）。
- **长篇/多章节项目绝不 `--all`**：小说改编动辄几十个章节脚手架，`--all` 会给每个未制作的
  空壳章节都烧一套双版封面；一律逐章 `--chapter`，做到哪章出哪章（与铁律9「文字先行」同向：
  没出图授权的章节封面也不出）。
- `--desc` 按本章剧情精写画面（角色姿势/氛围/场景），别用缺省的章节标题自动拼——封面是包装，
  值得一句认真写的 key visual 构图；desc 里**不写字**（标题另有题字段管）。
- **标题是 AI 画出来的设计元素（缺省两段式）**：①无字 key visual → ②AI 题字（logo 级字效、
  与画面光效融合；章节题字沿用系列封面字形锁系列感）。**题字后必须 Read 成品逐字查错字**
  ——引擎无 OCR，这一眼是唯一防线；错字/字形崩了就 `--force` 重滚，连滚两次还错就退
  `--typeset-title`（ffmpeg 排版后置，零成本字绝对精确）。
- **desc 写法＝封面元素六件套（固定规则·缺一即单调）**（判据：Netflix key art 研究 +
  动画海报构图理论 + 2024-2025 国漫海报四大主流打法「繁多元素堆叠/中心主体+环绕式构成/
  撞色反差/明暗对比」，引擎 DNA 七条工法栈同源）：
  ① **主角戏剧瞬间**：具体动作 + 有戏的表情（回望/迎向威胁/蓄势），构图带对角线动势；
  ② **配角/威胁层**：配角动势呼应主角，或反派/威胁剪影压在中远景；
  ③ **巨大世界观符号作背景**：吞没天幕的天象/庞然意象，尺度对比讲「世界之大与险」；
  ④ **题材符号环绕层（治「单调感」的钥匙）**：这部剧**独有**的标志物绕主角错落环布——
    直播剧＝弹幕光流/半透明属性面板残影/发光神币/在场观众数微光，修仙＝法阵符箓飞剑，
    机甲＝残骸零件全息图——没有这一层，画面就只剩「人物+天象」的空旷合影；
  ⑤ **框架性前景**：画框边缘虚化残片/光效碎屑半包围，锁视线进主体；
  ⑥ **色彩战略**：一个主导色 + 一处对撞色锚点 + 明暗对比强烈（对撞色**绝不安在吉祥物/
    正典配色的角色身上**——幽蓝的小满会被染成橙色布丁）。
  三条废稿自查：全员正对镜头排排站=废、面无表情=废、没有④的题材符号层=空旷单调=废。
  引擎工法栈会自动垫底，desc 只管「画什么」；阵容缺省=主角组（role 含「主」者优先）≤3 人，
  要更多人上封面在 desc 里显式点名。

> 上面的“六件套”只适用于角色/故事驱动的 key visual。其他 profile 必须把“主角/配角/威胁”
> 换成该题材真正的主主体、关系和环境层，但仍必须满足公共封面契约：系列与章节分离、标题与
> 元数据一致、3:4+4:3 双套、真实标题安全区、84px 缩略图可读，以及无字背景后置题字。

### ★节点③ · 配音（锁音色）→ 停下确认
```bash
python3 -m kinema tts --chapter demo/<章节> [--mock]
```
按 `shots[].speaker` 解析成角色固定音色，全程不漂移。生成后提示：**大屏章节详情里逐镜可听配音**。
某句不满意 → 改 `narration` 后 `tts --force`。**停下等确认**。
> **改了表现力字段怎么才生效（两条路，别记混）**：
> · 只改 `delivery.pause_before/after` → **重跑 `tts` 即可**，零成本（不重合成任何一句，
>   只按新停顿重算 `dur`、重拼 `narration.wav`、重写 `timestamps.json`）。仅 kenburns 生效。
> · 改 `narration` / `emphasis` / `note` / `emotion` / 音色 → **必须 `tts --force`**（或先
>   `review set --chapter <项目>/<章节> --shots N --stage audio --state retake`）：wav 已存在时
>   普通 `tts` 不重合成，改了也听不出变化；`--force` 会真的重新计费合成，旧版自动进版本栈。
>   已 `done` 锁定的镜 `--force` 也不覆盖，必须先置 retake。

### ★节点④ · 合成成片（kenburns 静图版）→ 停下确认

```bash
python3 -m kinema assemble --chapter demo/<章节>     # 字幕→背景乐→合成，一步到位
```
成片落 `project/demo/chapters/<章节>_work/output/`。提示：**大屏点该章节即可播放成片**。**停下等确认**。
> **合成前审阅闸（默认硬拦）**：`assemble` 出**正式成片**前逐镜查审阅态——kenburns 查
> `image`、dubbed/native 查 `clip`，有旁白镜另查 `audio`——**有一个不是 `done` 就拦截**并列出
> 待审镜 + 批准命令。想先看效果再审：`animatic`（零成本草稿，不受闸）；确要出草稿成片：
> `assemble --draft`（明确标注未过审）。`run`/`--auto` 不经此闸（收尾自动过审）。这道闸补上了
> 「免费合成」这步的防线——别让未过审产物悄悄变成成片。

### ★节点⑤ · 动态化（Seedance 图生视频）→ 停下确认
样片通过后让画面真正动起来，**二选一**（对白上镜的情景剧/角色扮演选 **native**+音色锚定；全旁白解说章选 **dubbed**）。
**⚠️ 花钱前必做（防黑盒烧钱）：先 `--dry-run` 列出每镜发给 Seedance 的完整提示词 + 成本预估供审阅**：
```bash
python3 -m kinema gen-video --chapter <项目>/<章节> --dubbed --dry-run   # 只列提示词+预估，不调 API、不计费
```
把提示词给用户审阅（可回改 `video_prompt`），**通过后去掉 `--dry-run` 正式生成——
加 `--approved-only` 只烧分镜图已批准(done)的镜**（设定图不齐的镜引擎自动拦截）：

**分辨率与 4K 二次授权**：默认按 config 档位（1080p）生成，无需额外确认。用户口头要 4K 时：
① 先 `--resolution 4k --dry-run` 出 **4K 档报价**（总价≈2×1080p，并发独享 1、RPM 15/分钟会排队）给用户；
② 用户**明确同意后**才加 `--resolution 4k --yes` 正式生成——不带 `--yes` 引擎会拦截，这是刻意的双保险，
不要替用户补 `--yes`。

**预留额度（事前闸，正式生成时自动跑）**：真跑前引擎会先把整批算清楚再决定发不发——
硬超项目 `budget`（已花 + 本批预估 > 上限）**一镜都不发**（账单为零，与"烧到一半才断"的事后闸不同）；
最贵一次调用超过顶层 `budget_per_call` 则要求 `--confirm-spend` 二次确认。
两条纪律：**① 拦下来时先把预估念给用户听，让用户决定是提额度、还是改用 `--approved-only` 少烧几镜——
不要自作主张去改章节的 budget**；**② `--confirm-spend` 与 `--yes` 是两把不同的钥匙**
（`--yes` 只授权 4K 档），同样不要替用户补。
dry-run 的逐镜清单是**全片**报价，收尾那行「本次真跑只发 N 镜」才是这次实际要烧的（断点续跑时两者差很多是正常的）。

**dubbed（固定音色对口型，全片音色一致）**——先有配音（节点③）：
```bash
python3 -m kinema gen-video --chapter <项目>/<章节> --dubbed --approved-only
python3 -m kinema assemble  --chapter <项目>/<章节> --dubbed   # 片段音频(我们的音色)+BGM+字幕
```
**native（原生音画，免 TTS，缺省全能参考·一镜一片）**——台词写进 `narration`，模型自配音：
```bash
python3 -m kinema gen-video --chapter <项目>/<章节> --native --approved-only
python3 -m kinema assemble  --chapter <项目>/<章节> --native   # 片段自带音画，不叠我们的 BGM
```
Seedance 按 providers 别名单价按秒计费、4K 翻倍（实价以 `config/models.yaml` 各别名 `price_per_second` 为准；
4K 须 `--resolution 4k --yes` 二次授权，见防烧钱铁律）。
**建议先只跑 1 镜验证**再放全片。**大屏看动态成片 → 停下确认 → 交付**。

### 素材直供模式（BYO / 资产复用，`supply` 命令）
无角色、以「固定场景 + 少量资产图」拼接的解说类视频（详细工法见 kn-showcase）：
分镜画面不必每镜生图——**资产首现镜正常 gen-image，复用镜用 `supply` 把已有图
登记为画面**（同图换 `camera` 运镜语义制造动态）：
```bash
python3 -m kinema supply --chapter <项目>/<章节> --shot 4 --file <图片路径> [--aspect 9:16]
```
直供与生成同制度：覆盖前旧版自动归档、登记后落待审、done 锁定拒改；
`gen.image.provider="supplied"`，生图阶段自动跳过直供镜（零生图成本）。
Studio 分镜卡「⇪ 素材直供」可直接上传本地图（落 `assets/supply/` 再登记）。

**登记前自动过一道供料体检**（零成本本地 ffprobe，CLI 与网页同一条闸）：
分辨率低于画布 / 宽高比与画布不符（Ken Burns 的 cover 取景会裁掉主体）/
带 alpha 通道（合成后透明区变纯黑）——三项**只告警不拦**，照常登记并留痕
`gen.image.inspect`；只有「ffprobe 解不出（改名的假图、损坏文件）」硬拦，
因为那种素材后续 ffmpeg 渲染必炸。**看到告警要转告用户**（例：「这张 640×360
只覆盖画布 33%，成片会糊，建议换高清版」）；用户确认素材不可再生、坚持登记时
加 `--skip-check`（网页在直供选择器底部有同款「跳过素材体检」勾选）。

### 决策留痕（`decision add`，跨会话不翻烧饼）
制作中做过的**有分量的取舍**——为什么这镜改远景、为什么整片走 native 而不是 dubbed、
为什么否掉了用户先前提的某个方案——用一条命令记进章节文档，下次会话（或别人接手）
一眼看到结论与理由，不会把已经推翻过的方案再提一遍：
```bash
python3 -m kinema decision add --chapter <项目>/<章节> \
  --choice "第3镜改用远景" --alt "中景" --alt "特写" --why "突出孤独感" --confidence high
python3 -m kinema decision list --chapter <项目>/<章节>     # 接手一个老项目时先看这个
```
三条纪律：
- **必须走命令，绝不直接往 project.json 里写 `decisions`**——裸改会被引擎长任务的旧内存副本
  或数据库里较新的库行静默覆写掉，且不会有任何报错（合并层只保证无 id 的裸写条目不会
  被复制成千上万份，救不了它被库行覆写）。
- **只记取舍，不记流水账**。一集通常 3~8 条；「跑了 gen-image」这种不是决策。
- append-only：只增不改不删。结论变了就**再记一条新的**（写清推翻了什么），历史保持可追。
用户明确表态否掉某个方案时（尤其是"不要 XX""还是用 YY 吧"），顺手记一条——这是本命令最大的价值场景。

### 全自动模式（用户说 `--auto` / "全自动" / "一次跑完" 才用）
跳过所有节点，一条龙跑完：
```bash
python3 -m kinema run --chapter demo/<章节> [--dubbed | --native] [--both] [--mock]
```
- **收尾自动过审**：`run` 成功收尾后引擎自动把本轮产物的待审（wfa）置为通过（done），
  全自动语义下不留审阅缺口；要保留待审供人工复核加 `--no-approve`；`--mock` 跑不自动过审。
- **封面随 run 收尾自动补**：系列主视觉缺席时一并出，本章封面按章节 `cover_prompt` > `theme`
  取画面命题（`--desc` 只有 `cover` 命令有）、副标题缺省「第 N 集」——run 前把 `cover_prompt`
  写进 ChapterPlan，别让封面退回 theme 拼句。多章一次补齐才用 `python3 -m kinema cover <项目> --all`
  （系列主视觉 + 全部章节封面，默认竖 3:4 + 横 4:3 双套）。
  ⚠ `--all` 只适合「章章都已制作」的小项目——长篇改编有几十个空壳章节脚手架时
  一律逐章 `--chapter`（见节点②.7），别给没做的章节烧封面。
