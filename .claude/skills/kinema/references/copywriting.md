# 短视频文案规范（节点① 的文字侧交付物）

> 分工：本文件管**说什么、怎么说**；`storyboard.md` 管怎么拍；`performance.md`
> 管怎么演。旁白文风有五个机器哨兵（lint 的 `narration_pivot` / `narration_jargon` /
> `narration_nominal` / `cta_grand` / `narration_opener`）——词表与正则的单一真源在
> 引擎 `engine/kinema/pipeline/variation.py`，本文只讲纪律、不抄表。
>
> **适用语态**：本规范服务**解说驱动（lead）**的口播文案。剧情驱动（sparse）的
> 正文是对白与画面——只有骨架三段（作剧情节拍梗概）与那少数几镜旁白点缀适用本文，
> 对白写作归人设口吻（`speech_style`）与 performance.md 管（语态见主 SKILL「语态先行」）。

## 〇、材料清点（动笔之前先数料——这是闸，不是建议）

一条视频立得住靠**材料**，不靠措辞。动笔前内部清点手里的具体材料，只认三类：
用户给的事实/数字/经历/原话；检索到的可核验案例与数据；明确获准虚构的情节。
你自己的常识复述、类别概括、「意义/风险/未来」式的展开，**都不算料**。

- **门槛：一条 30~60s 的片子至少 3 件具体材料**，且三件要能连成一条有先后因果的
  事，不能是三句相邻的道理。
- 数不够时按序走三条出路：① **能查就查**——WebSearch 完重新数（检索工具就在
  手边，没查过就说料不够，这个结论不成立）；② **一次问齐**——最多三个问题一次抛给用户，别挤牙膏；
  ③ 都走不通就**缩**：把片长砍到料撑得住的长度，绝不用套话灌满时长。
- 目标时长、用户催促、「直接写」都不能把材料变多。料不够就写短——8 镜说同一件事
  的四种说法（旁白空转）全部源于这一步没把住。

## 一、骨架：Hook → Body → CTA（黄金 3 秒是第一杠杆）

- **Hook（0~3s）**：1 句。平台从第一帧测留存，绝大多数观众在头几秒决定去留。
  三大最稳钩子：**反常识断言 / 错误警告 / 清单预告**，叠加认知触发
  （好奇缺口、模式打断、自我相关、情绪唤起）。
- **Body（3~20s）**：一句一个观点，兑现钩子的承诺；每 2~3 秒切一次画面（对应一个分镜）——这是口播/解说的节奏。
  剧情片与图生视频章节按镜长分档走 `video-prompting.md` 第七节，不套这个间隔。
- **CTA（末 3~10s）**：单一明确的行动号召，最好回环呼应开头（收尾纪律见第五节）。

**语速与字数**：说话人已有音色档案时，以 `voice bank` 里在用档案的 `speech_rate` 为准
（定制音色实测 2.9~4.2 字/秒不等），lint 会给出全章预计时长（`chapter_length_estimate`）；
没有档案才按中文口播 TTS 约 **4.3 字/秒** 估（15s≈65 字，30s≈130 字，60s≈260 字）。
分镜 lint 的语速带（`art_direction.density` 旋钮）按字/秒判；
英文口播约 125~150 词/分（15s≈40 词，30s≈75 词），只用于 `narration_en` 估长。
**「越短完播越高，优先 15~30s」只适用于口播/解说/带货**——剧情片与改编章节的
总时长由剧本自下而上推导（场→节拍→镜，见 `storyboard.md`《切分原则》），
常规落在 60~120s：为凑短时长砍设定、并句、删反应镜，砍掉的正是观众理解世界观
的那部分，完播率换不回叙事成立。

### 钩子的正面写法（反常识断言 ≠ 翻案句式）

**反常识断言 = 把反常识的事实本身直接说出来。**
「健身房三成会员，第二年一次都没去过。」——事实自带的反差已经是钩子。

**不是**「你以为办卡就会去健身？其实…」。先替观众虚构一个他并没有的误会、
再靠推翻它抬高下一句，是 AI 写钩子的默认句法，也是观众最先识别出的机器味。这一族句式
换多少套字面都是同一个动作（你以为…其实 / 看似…实则 / 不是…而是 / 与其说 /
从来不是 / 恰恰相反 / 回头才发现），lint 的 `narration_pivot` 按**句式族**拦。
判断从正面下、依据摆在旁边；只有内容真的走过「误解→修正」过程（比如翻车
后修正结论的评测片）才配得上翻案的形状。

## 二、写给耳朵（口播语言七纪律）

旁白是**念出来**的。听众没有回读能力——眼睛读着顺的句子，嘴里未必绕得开，
一切以念出来的那一版为准：

1. **主干先行**：先让主语和动作出现，再挂时间/条件/例子。定语超过一层就拆句——
   听丢的从来不是难词，是迟到的主干。
2. **一句一口气**：一口气念不完就拆成两句。逗号连缀四个小句的长龙，念的人断气、
   听的人断线。
3. **代词要找得到对象**：分镜一切，「它/这个/这里」必然失指——隔镜必须重新点名
   （这与画面提示词的点名铁律同源，见 `performance.md` 第二节）。
4. **新名词第一次说全**：全称先落地，之后才可用简称；一条片子里新名词 ≤3 个，
   多了谁也记不住。
5. **数字只留必须记住的**，且换成留得住的说法：「三成」比「31.7%」留得住，
   「一杯奶茶钱」比「14.8 元」留得住。
6. **动词不压成名词**：「实现了效率的提升」是公文，「快了一倍」是人话
   （`narration_nominal` 会抓「进行了…/实现了…/起到了…作用」这族公文骨架）。
7. **汇报腔词不进口播**：赋能/抓手/闭环/底层逻辑/组合拳/方法论/颗粒度…念出来
   像开会不像说人话（`narration_jargon` 逐词给改写方向）。

**整页的形状也要查**：同一个连接词起头 ≤2 镜——「其实…」「所以…」连开三镜，
复读感比任何用词重复都明显（`narration_opener` 数到 3 即报）。写完**读出声计时**
一遍再交：眼睛读着顺的句子，嘴里未必绕得开，以念出来的那一版为准——
这一步没有任何工具能替。

## 三、经典框架与漏斗位映射

| 框架 | 结构 | 适用 |
|---|---|---|
| **PAS** | Problem→Agitate→Solution | 痛点已知、<30s 短视频（默认首选） |
| **AIDA** | Attention→Interest→Desire→Action | 冷启动/陌生受众、30~60s |
| **BAB** | Before→After→Bridge | 转化型、漏斗中部 |

漏斗位：顶部 AIDA / 中部 BAB / 底部 PAS。

## 四、写作四步（缺一则空洞）

1. **清点**：过第〇节的材料闸，料不够先补料。
2. **框架**：定 PAS/AIDA/BAB 当脚手架，材料按框架落位。
3. **约束**：给自己可测试的约束——「130 字、每段含一个具体数字、无一个第二节
   禁的词」，不是笼统的"写好点"。
4. **自评重写**：按「具体性/可执行性」自评，重写最弱的一段；把检索到的具体数字、
   案例、反常识事实塞进钩子与痛点段——AI 产出的通病是"光滑但保守"，棱角
   （怪比喻、断句、让人停下刷的那一句）要人工加上去。

## 五、CTA 与收尾纪律

- 单一动作：只要一个行为（关注/收藏/评论区见），两个等于零个。
- 回环：能呼应开头的钩子最好——观众感到"这条片讲完了"。
- **收尾不升华**：时代/文明/历史/世界/未来/人类/奇迹/所有人——这批宏大词是机器
  收尾的默认动作。整条片子从没讲到这个量级的事，末镜突然抬上去只显空；把结尾收回到
  **具体的人、动作或数字**上（「明天路过那家店，进去看一眼配料表」）。lint 的
  `cta_grand` 只扫收尾镜、info 级——史诗/纪录题材本就在那个尺度，判断权在你。

## 六、平台风格差异（同一核心 → 三个版本）

视频可复用，但文案/标题必须按平台改写：

| 平台 | 风格 | 要点 |
|---|---|---|
| 抖音/TikTok | 生猛、口语、真实>精致 | 前 1~2 秒钩子；"关注更多"显生硬 |
| 小红书/Reels | 精致、值得收藏、干货角度、审美一致 | 引导 save & share；标题"前 10 字定生死" |
| YouTube Shorts | 清晰、关键词丰富、搜索导向 | 标题≤100 字含关键词；元数据比另两家更重 |

**通用**：字幕近乎强制（50~80% 用户静音看）；跨平台切勿带水印搬运（降权 40~60%）；
多平台要求披露 AI 生成（交付包 manifest 已内置披露位）。发布文案在节点①顺手填
`script.per_platform.{平台:{title,caption,hashtags}}`，`deliver` 直接取用。
