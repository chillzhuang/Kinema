# 视频提示词写作规范

本文件是 `shots[].video_prompt` 的创作真源，与 `storyboard.md` 互为索引。
先确定本镜使用的模型和实际素材，再安排动作；提示词长度不作为质量标准。
动作僵硬需同时检查动作设计、首帧、运动参考与模型结果，不能只归因于措辞。

## 1. 按生成任务分配内容

| 实际输入 | 作者重点写什么 |
|---|---|
| 单图首帧 | 从这张图出发的主体动作、方向、速度与相机跟随关系 |
| 多素材参考 | 本镜发生的事件；角色、场景、道具通过镜级绑定交给引擎映射 |
| 运动参考视频 | 需要参考的运动范围和必要差异；准确的动作参考无需逐拍重述 |
| 首尾帧 | 两个状态之间的过渡过程；避免再次描述两张图已经给出的外观 |
| 简笔板或 authored beats | 按事件顺序描述关键变化，正文只补未在拍序中表达的镜级信息 |

不同模型的格式不混用：引擎按 provider 的 `timeline_unit` 输出自然推进、顺序段或秒段，
不手写模型不支持的时间语法。参考素材的职责、首尾帧是否实发以 dry-run 为准。

## 2. 引擎与作者的分工

引擎统一编译画面基准、实际素材编号、单镜连续性、默认播放速率、音色与台词、
闭声要求和字幕后置约束。作者不重复这些固定说明，也不手写 `@图片N` 编号。
`camera` 集中到正文开头是组织方式，不把“前位 token 权重最高”当作模型保证。

已有运动设计时，引擎不再额外补充微动、起落缓冲或附属物运动。需要哪种表演就
明确写入本镜；静止、匀速、急停和持续运动都是有效创作选择。正文、增量、拍序
与运动参考全缺失时才保留原有保守兜底，并在生成前提示。

| 字段 | 职责 |
|---|---|
| `video_prompt` / `_en` | 简单镜的运动正文；有 beats 时只补跨拍信息，以及首帧或参考中尚未出现的主体、材质与环境 |
| `camera` | 主导运镜、起止构图与跟随关系；逐拍 camera 只写该阶段的变化 |
| `action` | 一句话说明核心事件；具体接触顺序和过程交给正文或 beats |
| `entry_state` / `end_state` | 开始与结束时的边界状态，不再复述完整动作；结束时可以仍在运动 |
| `light_shift` | 有叙事作用的光线变化，不重复逐拍光效 |
| `sketch.beats` | 关键事件、因果、接触顺序与必要卡点；每拍动作必填，其余按需 |
| `sfx` / `beats[].sound` | native 的声音事件；已有逐拍声音时不再重复镜级汇总 |
| `characters` / `props` / `scenes` / `refs` | 实际素材绑定，名字命中设定集 |

正文、结构化增量和 beats 不用不同措辞复述同一动作。引擎只消除直接重复，
不推断两段自然语言是否同义。有 authored beats 时，正文可以简短或省略；
有准确运动参考时，文字集中说明素材用途和需要改变的内容。
中英稿表达同一份设计；已有 beats 时，英文正文也不再复述整条时间轴。
两语种共享的结构化槽位只维护一份，不在英文补充稿里再写相反的速度、结尾或接触顺序。

## 3. 把动作写成可观察的结果

先写清谁做什么，再按需要补充方向、空间跨度、力度、速度或物体响应。
一个完整动作也能构成一镜，不强制“起—承—收”三拍，不强制每镜都有微表情、
次级动画、环境流动或光线变化。

示例：

> 白刻从庭院左侧起步冲刺，向右跨过低矮木栏，落地后保持跑势离开画面。
> 镜头侧向跟拍，保持全身和落脚区域可见。

若重点是手部，可以只写：

> 白刻迅速扣住滑落的杯柄，将杯子稳稳放回桌面。

细节服务于本镜的关键变化。打斗、舞蹈等复杂动作先明确主要动作和空间关系，
只对需要观众看清的动作补充力学、接触和受力反馈，具体方法见 `action-direction.md`。
动作幅度用位移、转向、跨越范围等可见结果表达，不依赖“更有动感”等空词。
减速、停顿与缓冲放在具体需要的位置，不给每个动作都加“先快后稳、落点制动、收势停住”。
例如交接物体可以写：

> 手臂穿过屏幕边界，将晶体递向右前景的人手，接近掌心时减速。
> 人手从下方承重后，恶魔手指松开并撤去支撑，空手沿来路退回屏幕。

接触、承重、松手与分离是关键因果；衣摆、粒子等细节只保留能帮助读清主动作的部分。
不靠缩小肢体幅度或让整个场景静止来维持身份一致。

## 4. 时长与拍序

镜长由动作、台词和叙事停顿共同决定，并满足在用 provider 的时长范围。
动作和说话可以同时发生，不把二者时长机械相加。不要为了默认镜长增加无意义的
蓄势或停顿；动作很短时可缩短镜头，需要更多事件时再扩展拍序。

简单连续动作使用正文即可。复杂调度、明确事件节点或预演板需要时才写 beats，
不因镜头超过某个秒数就强制拆拍。默认只写动作先后，需要卡点时才给 `t`。
引擎不按拍数均分、不按台词字数安排开口时间，也不把预演格数当成表演节奏。

| 时间表达 | 适用方式 |
|---|---|
| `natural` | 连贯叙述动作推进，不输出编号或秒段；未声明时间策略的模型默认采用 |
| `shot` | 顺序分段，适用于当前 Seedance 2.0 配置；不把段号写成机位切换 |
| `second` | 仅输出作者明确写出的秒段，缺 `t` 的拍只标顺序；当前 Seedance 2.5 配置采用 |

Seedance 2.5 优先用整数秒标主要事件，快速连续动作放在同一事件段内写清速度与
因果，不拆成每秒固定动作配额。已有小数秒原样保留，不自动取整或拉长；这不代表
模型能精确执行小数秒。重叠、非正时长和超出实际请求时长会拒绝编译；留白与局部
定时允许，但需核对衔接。并行动作放在同一拍描述，不用两条重叠秒段表达。

动作、对白起止和音效卡点共用这一份拍序。例如一镜先跑到门口再交谈：

- `0-4s`：白刻冲到门前刹住脚步，回头看向明川，此时无人说话
- `4-8s`：白刻催促明川离开，明川一边追上一边回答；脚步声持续

准确台词仍写 `lines[]`，由引擎逐字附带说话人及音色绑定；不要再写一份不同版本的
对白，也不要假设一句台词对应一拍。正文可用“跑到门前后开口”等相对关系，
只有需要明确时刻才写秒段。节奏验收以输出为准，字幕精确对齐以实测人声时间为准。

默认按正常速度表演；升格、慢放、子弹时间或延时摄影应明确表达。
优先写“迅速起身”“持续冲刺”等动作速度，不把每秒次数或 Hz 当作通用控制接口。
`end_state` 是结束时的状态，可以仍在奔跑或转身，不等于停稳或定格。

## 5. 分镜图与运动参考

分镜图要为接下来的动作提供可行姿态和空间。检查主体重心、必要肢体、移动路径、
障碍物和机位；起步或动作途中都可以，避免把尚未发生的目标动作先画成完成态。
坐姿可以起身再跑，只要镜长、构图和动作路径允许；近景也可以有迅速反应，
需要全身位移时应采用能容纳它的构图，而非一律弱化动词。

角色、道具和场景使用项目已有参考，画风沿用 `style_prompt` 单一真源。
局部修图明确需要改变和保持的部分，不每次重写整套形象。

运动参考先检查源片本身：人物是否真的移动、关键肢体是否有动画、动作是否被遮挡。
粗白模中未动画的四肢可能限制最终动作；不能靠正文同时要求“严格跟随”和另一套节奏。
深度捕捉、previz、sketch 按既有 guide 仲裁使用，不叠加多个运动权威。
源片只作为创作取材、未随请求附发时，不写“严格跟随所附源片”。把所需动作直接写入
正文或 beats，模型只接收本镜一套时间轴；源片时码与对拍说明留在审阅记录中。

字幕后置合成。视频防字规则只禁止额外字幕、未经要求新增的文字与标识、新增水印；
素材已有的界面字样、招牌或道具文字可以随透视、运动、景深和遮挡自然变化，不要求
钉在画面坐标上。必要时在正文明确它属于哪个物体，不同时在负面串里禁止所有画面文字。
图像生成仍按各 profile 的图像防字规则执行，不能用视频规则替代生图配置。

## 6. 审阅与迭代

生成前用 dry-run 审完整请求，重点核对素材职责、动作来源、时长、台词和音频模式。
一镜保留一个主导运镜；文字和图像之间的变化必须是有意设计，不能互相矛盾。
既有内容明确要求镜内蒙太奇时，剪辑点与机位变化写入拍序；引擎不再追加连续拍摄
要求，但不会据此自动拆成多个视频文件。不要为了规避约束而写无意义的切镜指令。
负面要求按 provider 能力使用，字幕和声音控制仍由引擎统一编译。
对白镜还要把 beats、`lines[].voice_instruction` 和正文的开口顺序对齐；手持道具在
真正放下之前不能同时出现在桌面上。审阅完整 PromptEnvelope，而非只看作者正文。

效果不好时一次调整一个变量：先动作稿，再首帧或运动参考，最后比较模型。
同时看动作完成度、肢体自然度和身份一致性，不能把相机移动当作主体动作改善。
保留既有版本与 PromptEnvelope 供比较；试片、报价和付费授权纪律不变。
