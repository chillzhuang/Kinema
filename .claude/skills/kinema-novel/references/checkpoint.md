## 0 · 三条前置

1. **结论是三态 `pass | fail | unverified`。** 取料缺失 = `unverified`，**不是 pass**。
   baseline 为空、上一章 state 缺、人设四件不全、本批没声明过 payoff——这些情况下
   那一门是**空转**，如实写 `unverified` 并写清缺什么。存疑一律记不通过。
2. **每条结论必须带出处**：第几章第几段、引用的人设卡/宪法原文、或某条 lint code。
   没有出处的结论在报告里等于没写。
3. **先确认这批真写完了**：`novel lint` 的 `gap` / `digest_missing` / `state_missing` /
   `manuscript_drift` 四类归零才开始复核。没归零就先补——在残缺的账上做复核，
   七门全部失真。

## 1 · 取料（两条命令，零成本）

```bash
cd engine
python3 -m kinema novel recap <pid> --from 66 --to 75    # 逐章概要表·伏笔动静·新实体·文体量化
python3 -m kinema novel lint <pid> --from 66 --to 75     # 账目恒看全书，文体只扫这一窗
python3 -m kinema novel arcs <pid>                       # 卷进度态与覆盖断档（第①门对照物）
```

需要追一个具体设定改动落没落全时，再加一条跨七层检索（正文/设定卡/digest/state/
卷纲/伏笔/宪法）：

```bash
python3 -m kinema novel sweep <pid> --term "熄灯令" --min-len 2
```

`recap` 的逐章概要表是 markdown 表，**直接贴进报告第一段**。三条数据纪律：`recap`
的数逐项数出来、不许估；`lint --level warn` 只看待办、`--json` 拿全量；每一个进报告的
数字都要能指回本次会话真跑过的这几条输出之一。

## 2 · 七门判据表

| 门 | 判什么 | 怎么判（判据与取料） | 不过怎么办 | 什么算 unverified |
|---|---|---|---|---|
| **① 合宪** | 本批正文有没有违反 `world_bible` 的力量体系/规则/**代价**；有没有在推进当前卷的 `goal`/`climax`/`turns` | 逐条把宪法里与本批相关的那几节摊开对正文核（代价条款最常被写飞：能力用了却没付账）；`novel arcs` 看本卷进度态与覆盖断档，逐章对 `recap` 表问「这一章推进了本卷目标的哪一步」 | **改正文，不是改宪法。** 确需改设定：先 `novel log <pid> --kind decision --at N --text "为什么改"` 留痕，再 `novel bible <pid> --section "力量体系" --file 新节.md` 只换那一节，然后 `novel sweep` 逐层回溯前文 | 宪法为空/没分节；`lint` 报 `arc_missing`（没有卷纲＝这一门没有对照物） |
| **② 人设** | 口吻是不是塌成一个腔；行为是否合 `personality` 与 `arc` 当前阶段；有没有踩 `taboo_lines` | 见 §3 盲测协议（出一个归属准确率 x/10 + 混淆对）；`character show <pid> --name 沈砚` 取卡；踩禁区的逐条摘原句 + 引用 `taboo_lines` 原文 | 就地改台词/改行为。**除非这一处就是要写他破戒**——那是弧光转折，须 `novel log --kind decision` 留痕并 `character set <pid> --name X --arc "…"` 更新弧光 | 参与盲测的角色里有人的 `speech_style` 或 `taboo_lines` 为空（那几个人的判定不成立，报告里逐个点名） |
| **③ 连贯** | 时间线/记忆/状态/资源/地理/名称/人称七类是否自洽 | 见 §4 —— **按类逐项扫，不通读**。取料 = 本批 10 章的 `digest` + `state`（`recap` 已列齐）+ 上一批最后一章的 `state` | 改正文；同时补上导致失配的那条账（多半是某章 `state` 写漏了持有物或时间） | 本批有章缺 `state`（`lint` 的 `state_missing`）——长程四类没有账本就判不了 |
| **④ AI 味** | 口癖、复读、说明书腔、排比腔、半角标点、markdown 污染 | 见 §5 两拍协议。数据面读 `lint` 的 `prose_slop`/`prose_repeat`/`prose_head_repeat`/`prose_bands`/`prose_markup`/`self_reference`/`ascii_quote`/`definition_sentence`/`parallel_triple` | 逐处改写（改的是写法不是删词）；确认要长期禁的词 `novel style <pid> --add-avoid "沉默了一瞬,不知过了多久"`，下批 lint 直接以 `style_avoid` 拦 | 本批正文不在盘上或 `manuscript_drift` 未清（扫的不是最新稿） |
| **⑤ 文风** | 对 `baseline` 文字样本比句长节奏/语域/叙事距离；数值面看 z 分 | 抽本批开头段与高潮段各一，与 `narrative_style.baseline` 并排读；`lint` 的 `style_drift` 给 `|z|>2` 的分量点名（`avg_sentence_len`/`sd_ratio`/`mattr`/`dialogue_ratio` 等）；`avoid` 词零容忍 | 改正文向基线收；若是**有意**的风格演进（换卷换调子），`novel baseline <pid> --from 66 --to 75` 重立数值基线并在报告里说明 | `lint` 报 `no_baseline`（没有样本＝这一门肉眼都无锚，空转）或 `no_baseline_metrics`（有样本无 z 分，只能肉眼判——如实注明） |
| **⑥ 伏笔与设定账** | 本批埋/收/仍欠/超期；本批新登场实体有没有登记；人设卡、图谱、宪法、卷纲是否落后于正文 | `recap` 的「伏笔动静」四个数 + 「本批首次登场的**已登记**实体」；`lint` 的 `thread_expired`/`thread_stale`/`char_absent`。**逐章 digest 里出现、却不在新实体表里的名字 = 漏登记** | 超期的当场选一条路：`novel thread-pay <pid> --id th12 --in 74` / `novel thread-set <pid> --id th12 --due 120 --tier mid`（延期须说得出理由）/ `novel thread-drop <pid> --id th12 --note "并入主线"`。漏登记的当场 `character add`/`scene add`/`prop add`；退场角色 `character set <pid> --name X --status departed` | 账本本身没建（`threads` 为空却明显埋过东西）——这时先补建账再判 |
| **⑦ 节奏** | 兑现密度与断章型的分布 | **opt-in**：只有本批用 `novel save --payoff/--hook` 声明过才有账。引擎给 `pacing_flat`/`pacing_flat_tail`/`payoff_kind_repeat`/`hook_monotone`/`arc_no_major`/`short_chapter`/`long_chapter`；工业口径对账：**小兑现每章 ≥1、中兑现每 3~5 章、大兑现每卷 1、连续平推不得超 3 章** | 下批开批时把缺的那一档排进去（在批次计划里写明第几章给什么）；已写的不为节奏返工，除非同型连用已到套路化 | 本批一章都没声明 `payoff`——引擎整段静默，如实记 `unverified` 并在下批开始声明 |

**引擎一个字都不判「爽不爽」，也不判 OOC、不判 AI 味。** 它只出间隔、计数、比值与
z 分；这七门的每一个 `pass`/`fail` 都是你签的字。

## 3 · 第②门：人设盲测协议

「遮住名字读得出是谁」在同一个上下文里**物理上做不到**——写台词的和判台词的是同一段
记忆，你已经知道答案。所以这一门要外包给一个没有前情的读者。

**做法**：开一个 fresh-context 子代理（Task 工具），只喂两样东西：

1. 从本批抽 **10 句台词**——**打乱顺序、去掉说话人、去掉上下文**，每句编号 1–10。
   抽样口径：覆盖本批出场的全部主要角色，每人至少 2 句，优先抽「情绪压力下的台词」
   （日常寒暄谁写都一样，区分不出）。
2. 全部候选角色的 `speech_style` 与 `taboo_lines` 原文（`character show <pid> --name X` 取）。

**刻意不喂**：正文上下文、创作意图、你的自辩、章号。它只做归属，不做鉴赏。

**要它回**：`{归属准确率 x/10, 逐句判定与它的理由, 混淆对（把谁认成了谁）, 每句引用的人设卡原文}`。

**怎么用这个数**：

| 准确率 | 判定 | 处置 |
|---|---|---|
| 9~10/10 | pass | 记数进报告即可 |
| 6~8/10 | fail（局部） | 只改混淆对涉及的那几句；若同一对反复混淆，多半是两人的 `speech_style` 本身写得太像——`character set --speech-style` 先把卡改得能区分，再改台词 |
| ≤5/10 | fail（全员一个腔） | 这是本批第一优先修项。逐角色定一条**可执行的口头标记**（句长/是否用问句反问/称谓/专业词密度），写进 `speech_style`，然后重写本批全部对白密集段 |

**纪律：子代理只用在检查点这一处。** 每章的三门自检一律 inline——过度用子代理复查
自己的工作是已知反模式（成本、延迟、以及子代理拿不到写作现场的取舍）。

**退档方案**（用户不希望引入子代理时）：仍做归属测试，但在同一上下文里做——先把 10 句
抄成一张只有编号和台词的表，只看着这张表和人设卡逐句判，判完再回去对答案。报告里
必须如实写「**同上下文盲测，可信度受限**」，并把准确率标注为参考值而非证据。

## 4 · 第③门：按类逐项扫（七类）

**不要「通读一遍找问题」**——在几万字上通读的召回率极低；按类引导的机械扫描能多逮出
数倍。七类逐类过，每类只盯自己那一件事：

| 类 | 取料 | 判据（一句话问自己） |
|---|---|---|
| **时间线** | 各章 `state.time` + `digest` | 绝对天数是否单调不倒退？跨章间隔与正文里的「三天后」对得上？（`state.time` 必须是绝对锚点，写「当晚」的那一章先补） |
| **记忆与知识** | `state.characters` 各人一句话 + 本批 digest | 谁在第几章知道了什么？有没有角色用了他还没听说的信息？（最高频的连贯事故，且最难被通读逮到） |
| **能力与状态** | `state.characters` 的身体状态 | 重伤/中毒/闭关/禁制按声明的时长持续了吗？下一章直接生龙活虎了吗？ |
| **资源账** | `state.characters` 的持有物 + 正文 | 钱、丹药、弹药、兵力、次数限定的能力——只因情节而变，不许静默复原 |
| **地理** | `state.location` + 场景登记 | 从 A 到 B 的路程与耗时在两处描写里一致吗？同一个地方的方位关系有没有翻面？ |
| **名称混用** | `novel sweep <pid> --term "旧称"` | 同一人/物/地有没有两个叫法且没在正文里交代过？改过名的旧称还残留在哪几层？ |
| **人称与视角** | 本批正文 | 视角有没有越界到 POV 角色不可能知道的信息？人称/时态与 `narrative_style` 的 `pov`/`tense` 一致吗？ |

**前四类是长程型**——跨十几章才暴露，肉眼在当章根本看不出，**只能靠 `state` 账本防**，
所以归批次复核，也所以 `state_missing` 会让这一门直接 `unverified`。
**地理/名称/人称是局部型**——当章自检就能根治；如果它们在检查点还成批出现，说明每章
第③步的连贯门在放水，在报告里点出来，别只改正文。

## 5 · 第④门：AI 味两拍协议

分两拍，**顺序不能颠倒**：

**第一拍 · 全量列候选。** 把本批所有可疑处**一处不落**地列出来，每处三件：章号 + 段落
定位 + **原句照抄**。这一拍**不做取舍、不判轻重、不写改法**——只记录。理由很实在：
让模型「只报严重的」，它会字面执行并真的漏检；先摊开，判断才有对象。
起点用 `lint` 的 `prose_slop`（已带每千字频次与出处章）、`prose_repeat`（复读原句）、
`prose_head_repeat`（段首雷同）、`prose_bands`（读数越界）、`prose_markup`、
`self_reference` / `ascii_quote` / `definition_sentence` / `parallel_triple`（这四条是硬规则，
有一处报一处），再补上引擎算不出的：万能场景过渡、情绪直白命名、四字套话堆叠、
每段都收在一个总结句上。

**第二拍 · 分流。** 逐条判三档：

| 分流 | 什么情况 | 动作 |
|---|---|---|
| **改** | 是套话、是复读、是说明书腔 | 就地改写——把抽象换成具体动作/物件/生理反应，别只是删词（删完剩一句白开水是更差的结果） |
| **留** | 是这本书的母题词、是角色的口头禅、是刻意的重复修辞 | 在报告里写一句「为什么可以留」，下次不再重复判 |
| **进 avoid** | 顽固口癖，已经连续两批出现 | `novel style <pid> --add-avoid "词1,词2"` —— 下批 lint 会以 `style_avoid` 直接拦，零容忍 |

`prose_bands` 的越界**恒是提示不是错误**（文体是选择）：低于「长句占比」带区多半意味着
节奏只有一档，低于 MATTR 多半是口癖榜的同一批词——先看榜再定夺，别为了让读数进带区
去改文风。

## 6 · lint code → 归哪一门

| lint code | 归 | 说明 |
|---|---|---|
| `gap` `digest_missing` `state_missing` `manuscript_drift` `manuscript_missing` `manuscript_orphan` | **前置** | 这四类（前四）归零才算这批写完；drift = 手改了正文没重登记，`novel reindex <pid> --archive` 重算全书 |
| `arc_missing` `arc_gap` `arc_overlap` `arc_uncovered` `arc_done` | ① | `arc_done` = 本章收卷，该做卷末复盘并立下一卷纲 |
| `thread_expired` `thread_stale` `thread_stale_more` | ⑥ | `expired` 必处置；`stale` 是无期限挂太久，`thread-set --tier` 给它个档 |
| `char_absent` `char_absent_more` | ⑥ + ③ | 真退场了就 `--status departed`（标了不再报）；没退场却消失十几章是连贯问题 |
| `style_avoid` `style_drift` `no_baseline` `no_baseline_metrics` | ⑤ | 后两条出现即该门 `unverified` |
| `prose_slop*` `prose_repeat` `prose_head_repeat` `prose_bands` `prose_markup` `prose_narration_heavy` `self_reference` `ascii_quote` `definition_sentence` `parallel_triple` | ④ | 全部进第一拍候选表 |
| `pacing_flat*` `payoff_kind_repeat` `hook_monotone` `arc_no_major` `short_chapter` `long_chapter` | ⑦ | `short_chapter`/`long_chapter` 恒报；其余四条在本批一章都没声明 payoff 时整段静默 |

| ① 合宪 | pass | 逐条核了宪法「灯律·代价」一节：本批四次点灯全部付了代价（69 章折寿、73 章失明三日）。卷二目标「查出熄灯人身份」推进到「确认不止一人」（75 章），在纲上。 |

| ④ AI 味 | pass（有留项） | 第一拍列出 23 处候选，第二拍：改 17 处（「沉默了一瞬」×6 全改成具体动作；三连顿号 9 处拆成两项）；留 4 处（「灯」相关母题词，属本书核心意象）；2 个词进 avoid（「不知过了多久」「心中一凛」）。`ascii_quote` 3 处已改全角。 |

## 8 · 报告写作两条纪律

1. **首次出现的内部标识必须带一句人话。** `th12` 写成「th12『灯芯上的名字』」、
   `payoff` 写成「兑现（本章给读者的回报）」、lint code 写成「`style_avoid`（命中了
   你定的忌讳词）」。用户读的是自己的书，不是这套工具的内部术语。
2. **每一个数字都要能指向本次会话真跑过的一次 `recap`/`lint`/`sweep` 输出。**
   凭印象写「大概三万多字」「伏笔差不多都收了」，比不写更糟——它让一份看着完整的
   报告变成失真的报告，而用户是拿它做方向决策的。第五段限 1~2 项也是同一个道理：
   一次给五个问题等于没给。
