# kinema-novel · 原创小说创作指挥层

把「AI 写长篇必崩」的五个根因逐一钉死：**上下文溢出**（`novel brief` 一次取齐、
宪法按节取，绝不整本回灌）、**记忆缺锚**（卷纲＋章末状态＋伏笔账本＋人设卡＋创作
日志全部落盘）、**风格漂移**（文风契约＋数值基线 z 分，绝不逐章复述风格）、**写完
不回写**（回写是独立步骤，漏一次崩一片）、**没有复核节律**（十章一批次，七门逐门过）。

**分工铁律**：引擎零 LLM——`novel` 命令只做登记/归档/取料/状态机/确定性体检；
**写正文、判文风、判人设、判连贯、判 AI 味全是你的活。引擎只交数，不交结论。**
所有命令在 `engine/` 下跑，前缀 `python3 -m kinema`（速查见 references/cli.md）。

---

## 0 · 七条铁律

**① 承诺即执行——不预告，只播报。**
> **结束回合前先看你的最后一段：如果它是计划、分析、问题、下一步清单，或一句还没
> 兑现的承诺，那就现在用工具去做它，别把它当收尾。**

合法的收尾只有两种：**A** 「第 65 章已登记。接着写 66–75。」并**在同一轮里真的往下写**；
**B** 「本轮到此（已写到第 70 章）。回复『继续』我写 71–75。」——明确交还控制权。
「接着写 66–75。」然后结束这一轮是**明令禁止的中间态**：字面是宣告、实际是停下，
这一轮既没交付也没交还控制权。用 B 时必须写明写到第几章。

**② 以批次为单位，批次内不逐章问。** 批次 = 10 章。开批宣布一次范围就开写，中途不
请示——逐章确认在长篇上是纯摩擦。**什么时候可以中途停，只有这三条**：

| 判据 | 例子 | 不属于这三条时怎么办 |
|---|---|---|
| **不可逆动作** | 要重写已写的 20 章、要推翻一条已用了 50 章的设定 | — |
| **真实的范围变更** | 用户要的和正在写的不是一回事 | — |
| **只有用户能给的输入** | 主线分岔该走 A 还是 B、这个角色该不该在此转变 | **记进《批次报告》第五段，先按你的判断往下写** |

三门自检连改 3 轮仍不过，按第三条停（那已经是「需要用户拍板」）。

**③ 写满一批必须先复核再续写。** 七门复核 + 《批次报告》落盘 + `novel log` 留痕 +
**停下问是否继续**。不许自己接着写下一批——批次边界是用户唯一的方向盘。

**④ 写完就回写，回写是独立步骤。** 崩设定的第一根因不是注入不够，是写完没回写。

**⑤ 只取该取的。** 每章开头 `novel brief`。绝不 Read 整份 project.json（长篇上它有
几 MB），绝不回灌正文，绝不跑不带折叠的 `novel show`。

**⑥ 三门未过不 `novel save`。** 登记的意思是「这一章我认了」。

**⑦ 写作期一张图都不出**（§5）。

## 1 · 开工与接手

**接手一本已有的书（跨会话冷启动是常态，不是例外）——四步没走完不写第一个字：**

```bash
cd engine
python3 -m kinema novel show <pid>                    # ① 折叠总览：进度/文风/最近日志/伏笔欠账
                                                          #    读回执里的 ✎ 日志行——那是上次复核的结论
python3 -m kinema novel arcs <pid>                    # ③ 当前卷 + 覆盖断档
python3 -m kinema novel brief <pid>                   # ④ 本章料（写前必读包）
```
② 在 ①③ 之间：读最近一份《批次报告》`project/<pid>/plan/batch-<from>-<to>.md`
（路径在 `novel show` 的日志行里）。**三条禁令**：不 Read 整份 project.json、
不跑 `novel show --all`、不回灌正文。

**从零开工**（立项/立契/立卷纲/登记角色/写宪法）→ **Read references/setup.md**。
里面还有「续作与接盘导入清单」和「一个 pid 只放一本书」的边界。

## 2 · 批次协议

```
宣布批次 ──▶ 逐章五步闭环（不逐章问） ──▶ 满 10 章 ──▶ 七门复核 ──▶《批次报告》落盘 ──▶ 停下问
   ▲                                                                                    │
   └───────────────────────────── 用户说「继续」 ◀───────────────────────────────────────┘
```

**开批**：一句话宣布范围、属第几卷、本批要回收哪条伏笔、要埋什么，然后**立刻开写**。

**批次内**：每章走 §3 五步，逐章 `novel save`。一轮写多章、批量登记是正常吞吐——
但**每章必须当场 save**（登记＝「我认了」，攒着 save 会让崩溃时丢掉整批）；
digest / state 可以批末统一补，**但必须在检查点之前补齐**。

**这批算不算写完，有一条机械判据**——`novel lint <pid> --from N --to M` 的这四类归零：
`gap`（章号断档）· `digest_missing` · `state_missing` · `manuscript_drift`（正文改了没重登记）。

**一轮上下文写不完一批**（常态，10 章约 2~4 万字）：按铁律①形态 B 收尾，写明写到第几章；
下一轮**必须重跑 `novel brief`**（跨轮之后内存里的前情已经不可信）。

用户说「写完这本书」/「一直写下去」时**仍然按批次推进**，每批末出报告并问一句——
检查点的价值就在于**在错误扩散前**逮住它，跳过它等于把 100 章的返工风险攒到最后。

## 3 · 每章五步闭环（一步不跳、顺序不换）

**① 取料** `novel brief <pid>`——一次拿齐文风契约（含 baseline）、**按本章相关性选出的
宪法节**（缺省给全目录 + 自动选中的几节；要别的节 `--bible 关键词,关键词`，全量 `--bible all`）、
当前卷纲与节拍、上一章 digest 与 state、未回收伏笔（快到期的排前面）、在场角色人设卡。
同一会话连写多章、宪法已在上下文里时加 `--no-bible`。回执里两条**必须当场处理**：
「⚠ 角色表里没有 XXX」= 漏登记，`character add` 补；「⚠ 人设卡不全」= 这些人的第②门
盲测是空转，`character set` 补足。

**② 写正文**，落成 `.md`。写之前 **Read references/craft.md**——一章四拍（接/推/转/钩）、
断章七型、对白三步、开篇三章的验收问题都在里面。埋新伏笔当场
`novel thread-add --title … --setup N --tier short|mid|long`；本章回收的当场 `thread-pay`。
**正文里不许出现 markdown 排版**：`**加粗**` 只留给面板/系统文本，`---` 只在真的要断场时用
（写岔了不必手改，`novel normalize <pid>` 一键剥掉非面板加粗，旧稿自动进版本栈）。

**③ 三门自检**（对刚写的正文逐门过，不过就地重写该段）：

- **风格门**：抽开头段与高潮段，与 `baseline` 并排比句长节奏/语域/叙事距离；
  `avoid` 词零容忍；人称时态对 `pov`/`tense` 核一遍。
- **人设门**：逐角色扫台词与行为——口吻对 `speech_style` 盲测（遮住名字读得出是谁）；
  行为对 `personality` 与 `arc` 的**当前阶段**；**命中任何一条 `taboo_lines` 直接打回**
  （除非剧情就是要写他破戒——那是弧光转折，须 `novel log --kind decision` 留痕
  并 `character set --arc` 更新）。
- **连贯门**：对上一章 `state` 核位置/时间/持有物/在场人；对宪法核规则与代价；
  对 `graph` 核关系口径；对**当前卷纲**核这一章是否在推进本卷目标（跑偏就是跑偏，
  不要自我说服）。

顺手扫一遍 references/prose-rubric.md 的 AI 味清单（这一遍是自查，检查点那一遍是复核）。

**④ 登记** `novel save <pid> --no N --file 正文.md --title "…" [--digest "…"] [--state s.json]`
（要算第⑦门节奏账就加 `--payoff minor|medium|major --payoff-kind … --hook …`）。
引擎回执必读：**实体命中清单里没有、正文里却反复出现的名字 = 你漏登记了设定**。

**⑤ 回写**（独立步骤，绝不「顺手」）：`novel digest` + `novel state` + 设定变更。
清单与命令 → **Read references/writeback.md**。state 五键与写法：

```json
{"time":"入圈第四日", "location":"西九号死哨",
 "characters":{"陆昭":"接哨·索三样·内判芯病","燧":"将带路上哨顶"},
 "hooks":["西九的芯哪去了（th408）","燧的哨顶诊断在即"], "note":"接哨仪式=灯的交接"}
```
`time` 写**绝对锚点**（第 N 天/具体日期）不写「当晚」；`characters` 只记与下一章相关的人，
每人一句话须含位置/身体状态/持有物中至少两项；`hooks` 是未解决的悬念栈不是剧情复述。

## 4 · 检查点（★ 满 10 章自动做，不等用户催）

取料两条，零成本：`novel recap <pid> --from N --to M` + `novel lint <pid> --from N --to M`。
**引擎给的是数，七门的判定是你的活。**

七门：**① 合宪 ② 人设 ③ 连贯 ④ AI 味 ⑤ 文风 ⑥ 伏笔与设定账 ⑦ 节奏**。
每门的判据、取料、盲测协议、lint code **归哪一门**、《批次报告》七段模板 →
**检查点开始时整份 Read references/checkpoint.md**。

三条硬纪律写在这里，别等读到那份文件才知道：

- **每条结论必须带证据出处**（第几章第几段、引用的人设卡或宪法原文），
  且必须能指向本次会话真的跑过的一次 `recap`/`lint`/`sweep` 输出。
- **结论是三态 `pass | fail | unverified`**。取料缺失就是 `unverified` 而**不是 pass**——
  baseline 为空、上一章 state 缺、人设四件不全时，那一门是空转不是通过。存疑记不通过。
- **报告先落盘再贴给用户**：`project/<pid>/plan/batch-<from>-<to>.md`，然后
  `novel log <pid> --kind checkpoint --at M --ref plan/batch-N-M.md --text "…"`。
  跨会话接手的第 2 步读的就是它——不留痕等于这次复核没发生过。

## 5 · 图片留空（写作期的硬纪律 · kinema 铁律9）

**写小说期间一张图都不生成。** 设定登记的是**文字**（外貌/服装/发型/武器/keywords/desc
写足写细，它们既是给读者的描写素材，也是将来出设定图的提示词源）；
`characters[].sheet` / `props[].sheet` / `scenes[].sheet` **空着就是正常状态**。

**禁跑**：`project refs` / `gen-image` / `cover` / `refine`（`--mock` 一并禁——占位图会填满
`sheet`，之后分不清哪些真出过）。理由不是省事：一本书几十个角色几十处场景，设定到第 30 章
还会变（弧光推进、换装、断剑），**早出的图会被剧情作废，钱无效支出**。

**收口**：写到约定进度或全书完稿时出一张《出图就绪表》（各数 `sheet` 为空的项 ×
该 profile 的 `price_per_image` 报总价量级），**然后停下等指令**。用户说「出图」才动手，
没点范围时默认只出**主要角色 + 核心场景**那一小批先看效果。

## 6 · 与成片链的衔接

小说是上游资产。要做成视频时：`novel export <pid> --strip-markup` 导出纯文本 →
`adapt import <pid2> --file <导出文件>` → 按 kinema-project「3.5 剧本改编模式」
拆书分集 → kinema 主流程成片。**分集与原著章节一一对应：小说有多少章，视频就有多少
章节（一章=一集=一个分镜脚本，绝不合并章节——多章压一集会丢关键情节与设定）**。
`characters[]` 的文字人设四件直接沿用（台词口吻在分镜 `narration` 对白里同样受人设门
约束）；`arcs[]` 的卷纲作各集的节奏与批次参考，不改变一章一集的对应关系。
**改编期同样文字先行**：分集、拆镜、写 `image_prompt` 全做完再出《出图就绪表》——
这时才是真正该出图的时点（设定已被全书正文锤定，不会再改）。

**七条禁令**：绝不裸改 `project.json`（`threads`/`arcs`/`novel`/`narrative_style`/
`world_bible`/设定数组全部有命令）· 绝不把风格描述复述进每章提示（用 baseline 比对）·
绝不整本回灌当上下文 · 绝不在三门未过时 `save` 交差 · 绝不跳过批次检查点直接续写 ·
绝不用「接着写 X–Y」当一轮的收尾 · 绝不在写作期出图。
